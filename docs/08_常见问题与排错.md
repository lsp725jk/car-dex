# 第一部分：实际踩过的坑

## ⚠️ 坑 1：分类头学习率过大导致训练发散（最严重）

**现象**：

```
epoch  1/2  train_loss=4.8655  acc=0.0539
epoch  1/2  train_loss=4.8655 | val_loss=41.2589 val_acc=0.0229 MacroF1=0.0038
epoch  2/2  train_loss=14.4426 acc=0.0654
epoch  2/2  train_loss=14.4426 | val_loss=2889.5282 val_acc=0.0294 MacroF1=0.0068
```

验证损失 **2889**（正常应该是 `log(51) ≈ 3.9` 附近），Macro-F1 卡在 0.007。

**原因**：配置里写了 `"head_lr_mult": 10.0`，而 `lr=0.01`，
于是分类头的实际学习率是 **0.1**。分类头是随机初始化的，
0.1 的 SGD 学习率会直接把权重推到发散。

**修复**：把 `head_lr_mult` 改成 `1.0`（分类头与骨干同学习率）。

**如何自查**：看训练日志里的 `lr=` 值，以及 `val_loss` 是否远大于 4。
**经验法则**：微调预训练模型时，如果要用差分学习率，
`head_lr_mult` 从 2 开始试，同时把 `lr` 降到 0.005 左右。

## ⚠️ 坑 2：ResNet50 预训练权重用错版本，触发联网下载

**现象**：

```
Downloading: "https://download.pytorch.org/models/resnet50-11ad3fa6.pth"
  to C:\Users\y/.cache\torch/hub/checkpoints/resnet50-11ad3fa6.pth
RuntimeError: 加载 resnet50 预训练权重失败（[Errno 13] Permission denied: ...）
```

**原因**：本地缓存的是 `resnet50-0676ba61.pth`，它对应
`ResNet50_Weights.IMAGENET1K_**V1**`；
而代码里写的是 `IMAGENET1K_**V2**`，对应另一个文件名 `resnet50-11ad3fa6.pth`，
本地没有 → torchvision 尝试下载 → 无网环境失败。

**修复**：`src/cardex/models.py` 里固定使用 V1，并加了注释：

```python
SUPPORTED = {
    # 权重枚举必须与本地已缓存的权重文件名一致，否则会尝试联网下载：
    #   resnet18-f37072fd.pth         <= ResNet18_Weights.IMAGENET1K_V1
    #   resnet50-0676ba61.pth         <= ResNet50_Weights.IMAGENET1K_V1   (注意不是 V2)
    #   wide_resnet50_2-9ba9bcbe.pth  <= Wide_ResNet50_2_Weights.IMAGENET1K_V2
    "resnet18": (models.resnet18, models.ResNet18_Weights.IMAGENET1K_V1),
    "resnet50": (models.resnet50, models.ResNet50_Weights.IMAGENET1K_V1),
    ...
}
```

**如何自查**：运行下面这行，能成功加载就说明权重没问题：

```bash
python -c "from torchvision import models; models.resnet50(weights=models.ResNet50_Weights.IMAGENET1K_V1); print('OK')"
```

## ⚠️ 坑 3：`DataLoader(num_workers>0)` 被沙箱禁止

**现象**：

```
File "C:\ProgramData\anaconda3\Lib\multiprocessing\connection.py", line 575, in Pipe
    h2 = _winapi.CreateFile(...)
PermissionError: [WinError 5] 拒绝访问。
```

**原因**：运行环境的文件沙箱**禁止创建命名管道**，
而 PyTorch 的 DataLoader 多进程模式依赖 multiprocessing 的 Pipe。

**修复**：所有配置里都设 `"num_workers": 0`。

**代价**：数据加载与计算串行，实测约损失 30% 吞吐
（数据加载单独 188 img/s，计算单独约 70 img/s，串行合成约 50 img/s）。

**在不受限制的环境下**：改成 `4` 并配 `persistent_workers=True` 即可提速。

## ⚠️ 坑 4：`unknown` 目录排序错位，指标算出 0.06（最隐蔽）

**现象**：`finalize.py` 首次运行输出

```
排名 improved_resnet18_224   标定后 0.0648   未标定 0.0634
```

Macro-F1 = 0.0648，而单模型评估明明是 0.9482。

**原因**：脚本为了对齐"图片顺序 ↔ 标签顺序"，对**全部文件名做了全局排序**：

```python
names_sorted = sorted(truth)     # ❌ 全局排序
```

但 `unknown/` 目录下的文件名沿用的是**来源类别 ID**
（例如 `0022_0022.jpg` 实际是 unknown，来源类别是 0022）。
全局排序会把它们插到 **0022 类中间**；
而 `CarDataset` 的遍历顺序是"先按类别目录名排序"，
`"unknown"` 字符串大于 `"0987"`，所以 unknown 排在**最后**。

两者错位 → 预测与标签完全对不上。

**修复**：直接取 `CarDataset.samples` 的顺序，不再自己排序：

```python
ref_ds = CarDataset(paths.DATA_DIR / split, transform=build_transform("eval", 224, {}))
names  = [Path(p).name for p, _ in ref_ds.samples]
y_true = np.array([lab for _, lab in ref_ds.samples])
```

**影响范围**：`src/finalize.py` 与 `src/ensemble.py`（两个都已修复）。

**如何自查**：任何"评估脚本算出来的分数与 `evaluate.py` 差很多"的情况，
第一件事就是检查样本顺序是否一致。

## ⚠️ 坑 5：bf16 与 fp32 推理不一致，指标漂移 0.0005

**现象**：

| 来源 | 基线 Macro-F1 |
| --- | --- |
| 训练日志（bf16） | 0.847508 |
| `evaluate.py`（fp32） | 0.847011 |

差 0.0005。

**原因**：训练时启用了 `amp=true`（bf16 autocast），
训练结束时的最终评估也是 bf16；
而 `evaluate.py` 默认用 fp32。极小的数值差异让个别样本的 argmax 翻转。

**修复**：`evaluate.py` 改为**默认读取 checkpoint 里记录的 `amp` 设置**：

```python
amp = bool(ckpt.get("train_config", {}).get("amp", False)) if args.amp is None else args.amp
```

修复后两侧完全一致：基线 0.847508 / 类别平衡 0.842818 / 改进 0.948215。

**如何自查**：任何时候"重算的指标和记录的指标对不上"，先查推理精度是否一致。

## ⚠️ 坑 6：`evaluate.py` 的输出目录算错

**现象**：`evaluate.py` 把结果写到了 `outputs/checkpoints/runs/<run>/` 而不是 `outputs/runs/<run>/`。

**原因**：

```python
out_dir = ckpt_path.parent.parent / "runs" / ckpt_path.parent.name   # ❌
```

`best.pt` 的 `parent` 是 `outputs/checkpoints/<run>`，
再 `.parent` 是 `outputs/checkpoints`（不是 `outputs`）。

**修复**：

```python
out_dir = paths.RUN_DIR / ckpt_path.parent.name     # ✅
```

**同类问题还出现在 `predict_batch.py` 的标定文件查找**（同一个错误模式），已一并修复。

**教训**：多层 `.parent` 很容易数错，**优先用 `paths.py` 里的常量**。

## ⚠️ 坑 7：`CarClassifier` 初始化顺序导致 AttributeError

**现象**：

```
File "cardex/inference.py", line 81, in _training_log_prior
    n_c = [1] * len(self.label_names)
AttributeError: 'CarClassifier' object has no attribute 'label_names'
```

**原因**：`__init__` 里先算 `self.log_prior = self._training_log_prior()`，
但 `self.label_names` 是在后面几行才赋值的。

**修复**：把 `log_prior` 的计算移到 `label_names` 赋值之后：

```python
self.log_prior = None            # 先占位
...
self.label_names = list(self.ckpt["label_names"])
if self.prior_adjust_tau:
    self.log_prior = self._training_log_prior()
```

## ⚠️ 坑 8：PowerShell 的 `ConvertTo-Json` 把配置文件格式改丑

**现象**：用 PowerShell 批量改配置后，JSON 变成了

```json
{
    "run_name":  "baseline_resnet18_160",
    "aug":  {
                "crop_scale":  [
                                   0.70,
                                   1.0
                               ],
```

（值前面多两个空格、数组被拆成多行）

**原因**：`ConvertTo-Json` 的默认格式化风格与 Python 的不同。

**修复**：用文本工具（`edit` 工具或 `write` 工具）手工重写，
或统一用 Python 脚本改配置：

```bash
python -c "import json,pathlib; p=pathlib.Path('configs/x.json'); d=json.loads(p.read_text(encoding='utf-8')); d['threads']=12; p.write_text(json.dumps(d,ensure_ascii=False,indent=2),encoding='utf-8')"
```

**功能上没影响**（JSON 依然合法），但可读性差，且报告里引用的配置字符串会很难看。

## ⚠️ 坑 9：传入 logger 后训练日志不再写入文件

**现象**：训练跑起来了，控制台有输出，但 `outputs/runs/<run>/train.log` **不存在**。

**原因**：`train.py` 先调了 `get_logger("train", None)`（无文件 handler），
再把它传给 `engine.train_model(cfg, logger=logger)`；
而 `train_model` 里写的是

```python
logger = logger or get_logger(f"train.{run_name}", run_dir / "train.log")   # ❌
```

`logger` 已经非空，所以右边的 `get_logger(...)` **根本不会执行**，文件 handler 从未被创建。

**修复**：改成无论是否传入 logger，都确保挂上文件 handler：

```python
logger = logger or get_logger(f"train.{run_name}")
logger = get_logger(logger.name, run_dir / "train.log")     # ✅ 幂等地追加文件 handler
```

同时把 `get_logger` 改成"流 handler 与文件 handler 分别幂等添加"。

## ⚠️ 坑 10：`finalize.py` 的 meta 文件名与 `predict_batch.py` 不一致

**现象**：根目录同时存在 `predictions.meta.json` 与 `predictions.csv.meta.json`，
其中 `predictions.meta.json` 是**旧的**（记录的是 C1 单模型），
容易误判当前 `predictions.csv` 是用什么生成的。

**原因**：`predict_batch.py` 写 `out.with_suffix(".meta.json")` → `predictions.meta.json`；
`finalize.py` 写 `Path(str(out) + ".meta.json")` → `predictions.csv.meta.json`。

**修复**：统一成 `out.with_suffix(".meta.json")`，并删掉旧文件。

## ⚠️ 坑 11：`DataLoader` 在 Windows 下的中文路径 / 编码问题

**现象**：PowerShell 里跑 Python 脚本，中文输出显示为乱码（如 `棰勬祴`）。

**原因**：这是**控制台显示编码**问题，不是文件编码问题。
Python 的 stdout 编码与 PowerShell 的控制台编码不一致。

**处理方式**：
- 加环境变量 `$env:PYTHONIOENCODING="utf-8"`（本项目所有命令都加了）；
- 或者直接**读文件**（`train.log`、`report.json` 本身是 UTF-8，内容完全正确）；
- 或者把结果重定向到文件再查看。

**重要**：这只影响"在终端里看"，**不影响任何文件的正确性**。

## ⚠️ 坑 12：CPU 线程开满反而更慢

**现象**：`torch.set_num_threads(16)`（等于逻辑核数）时吞吐 38.2 img/s，
改成 12 后变成 46.2 img/s。

**原因**：**超订阅**——16 个计算线程 + 主线程的数据加载互相抢占，
上下文切换开销超过了并行收益。

**修复**：配置里统一 `"threads": 12`。

**实测数据**（resnet18@160 完整训练步）：

| 线程 | 吞吐 |
| --- | --- |
| 6 | 36.5 img/s |
| 8 | 39.8 img/s |
| 10 | 42.8 img/s |
| **12** | **46.2 img/s** |
| 16 | 38.2 img/s |

**换机器时建议重新测一遍**，不要照搬 12。

## ⚠️ 坑 14：配置文件在 PowerShell 里被 `Set-Content` 写成带 BOM

**现象**：用 `Set-Content -Encoding UTF8` 写的 JSON，在 Python 里读会报
`json.decoder.JSONDecodeError: Expecting value: line 1 column 1`。

**原因**：Windows PowerShell 5.1 的 `-Encoding UTF8` 会写入 **BOM**。
（PowerShell 7 的 `utf8` 默认无 BOM。）

**修复**：用 Python 写文件（`pathlib.Path.write_text(..., encoding="utf-8")` 不加 BOM），
或用 `-Encoding utf8NoBOM`（PS7）。

**注意**：`classes.txt` **明确要求无 BOM**，所以这个坑对它尤其致命。
`select_classes.py` 里有一行断言专门防御：

```python
assert not raw.startswith(b"\xef\xbb\xbf"), "classes.txt 不能带 BOM"
```

## ⚠️ 坑 15：报告里的数字写错（品牌数 36 vs 37）

**现象**：`configs/selection.json` 的原则 P3 里写"50 类覆盖 **36** 个品牌"，
报告里也照抄了。实际统计是 **37** 个品牌。

**原因**：早期手写原则时凭印象估的，没有用脚本核。

**修复**：

```bash
python -c "import json,collections; cm=json.load(open('configs/class_map.json',encoding='utf-8')); \
ci={r['id']:r for r in json.load(open('configs/class_info.json',encoding='utf-8'))}; \
ids=[cm['index_to_id'][str(i)] for i in range(50)]; \
b=collections.Counter(ci[i]['name_from_new'].split('_')[0] for i in ids); \
print('brands:',len(b),'| 2类:',sum(1 for v in b.values() if v==2),'| 1类:',sum(1 for v in b.values() if v==1))"
# brands: 37 | 2类: 13 | 1类: 24
```

**教训**：**报告里所有数字都应该来自脚本输出，不要凭记忆写。**

## ⚠️ 坑 16：`positional` 参数缺失导致新手困惑

**现象**：


# 第二部分：通用 FAQ

## Q1：`predictions.csv` 的分数和我算出来的不一样？

**排查顺序**：

1. 看 `predictions.meta.json`，确认它是**哪个模型**、**哪组 τ/t**、**是否开了 TTA** 生成的；
2. `python src/score_predictions.py` —— 它会用本地真值独立核算并打印；
3. 确认比较的是**同一个划分**（`--split val` 还是 `train`）；
4. 若 `predictions.csv` 是对**外部目录**生成的，本地没有真值，核算会失败（正常）。

---

## Q2：训练中断了怎么办？

**现状**：`train.py` **不支持自动续训**。

**手动恢复的思路**：

```python
import torch
from cardex.engine import build_model   # 注意：实际在 cardex.models
ckpt = torch.load("outputs/checkpoints/<run>/last.pt", map_location="cpu", weights_only=False)
model = build_model(ckpt["arch"], num_classes=ckpt["num_classes"], pretrained=False)
model.load_state_dict(ckpt["model_state"])
# 然后自己写训练循环，从 ckpt["epoch"]+1 继续
```

**更简单的做法**：重新训练（本项目 A/B 只要半小时，是可行的）。
长训练（C2 约 3 小时）建议先跑冒烟测试确认配置无误再启动。

## Q4：`outputs/` 被误删了怎么办？

- `outputs/checkpoints/` 删了 → **必须重新训练**（模型文件不可再生）；
- `outputs/runs/` 删了 → 日志丢了，但模型还在，可以用 `evaluate.py` / `calibrate.py` 重新生成大部分指标；
- `outputs/reports/` 删了 → 大部分可以重新生成：
  ```bash
  python src/select_classes.py      # 选类报告
  python src/data_analysis.py       # 数据分析
  python src/make_reports.py        # 实验对比与图表
  python src/finalize.py ...        # 最终模型比选
  ```

## Q5：显存/内存不够？

**本项目用的是 CPU**，不存在显存问题。内存峰值约 900 MB。

如果换到 GPU 后 OOM：

- 降 `batch_size`（32 → 16 → 8）；
- 降 `image_size`；
- 关掉 `amp`（有时 AMP 会额外占用）；
- 换更小的 `arch`。

**注意**：降 `batch_size` 后应该按比例降 `lr`。

---

## Q6：训练太快结束了 / 精度上不去？

| 症状 | 可能原因 | 处理 |
| --- | --- | --- |
| 几百秒就"训练完成" | 用了 `--limit-train-per-class`（冒烟模式） | 去掉该参数 |
| 精度一直卡在很低 | 学习率过大（看 `val_loss` 是否 >10） | 检查 `lr` 与 `head_lr_mult` |
| 精度一直卡在很低 | 预训练权重没加载成功 | 检查 `models.py` 的权重枚举 |
| 精度提升到一半就不动了 | `epochs` 太少 | 强增强配方需要更多轮 |
| 训练集 100%、验证集很低 | 过拟合 | 加强增强、开 EMA、开标签平滑 |
| 验证集比训练集还高 | 正常现象（强增强） | 不用担心，看 Macro-F1 即可 |

## Q7：怎么知道我的改动是不是变好了？

**原则**：永远用**验证集 51 类 Macro-F1** 判断，不要看训练准确率或损失。

```bash
python src/train.py --config <你的配置> --run-name my_test
# 然后对比
python src/make_reports.py --runs <基线run> my_test
```

**注意**：单次运行的差异小于 **0.005** 时，不能确定是真实改进还是随机波动
（本项目没有跑多种子重复实验）。

---

## Q8：`verify_submission.py` 报了 FAIL 怎么办？

每一项 FAIL 都写明了具体原因。常见几类：

| FAIL 内容 | 原因 | 修复 |
| --- | --- | --- |
| `classes.txt` 行数不是 50 | 手工改过 | `python src/select_classes.py` 重新生成 |
| 索引 0~49 顺序与 `classes.txt` 不一致 | `class_map.json` 与 `classes.txt` 不同步 | 同上 |
| `train/` 下缺少某个车型目录 | `data/` 不完整 | `python src/prepare_data.py --force` |
| train / val 文件名有重叠 | 数据抽取异常 | 同上 |
| `predicted_label` 有非法值 | `predictions.csv` 用了不在 50 类里的 ID | 检查模型与 `class_map.json` 是否匹配 |
| checkpoint 内的类别映射与 `classes.txt` 不一致 | **换了选类但用了旧模型** | 必须重新训练 |

## Q9：为什么 `make_reports.py` 里看不到某个实验？

因为 `--skip-smoke` 默认开启，会跳过 run 名以 `smoke` / `probe` 开头的实验。
要么改 run 名，要么显式指定 `--runs smoke_xxx`。

## Q10：`ensemble.py --limit` 的分数为什么完全不对？

`--limit` 是**按路径排序后截断**，只会取到开头几个类别的图片，
其余类别的验证样本数为 0 → 那些类的 F1 记为 0 → Macro-F1 严重偏低。

**`--limit` 只用于冒烟测试代码路径，不要用它评估指标。**

---

## Q11：`--tta-hflip` 到底该不该开？

**评估时**：应该开，且必须与你训练配置里的 `tta_hflip` 保持一致，
否则"评估出来的分数"与"训练日志里的分数"会不一致。

**推理时**：应该开（约 +1% 精度），除非推理时间是不可接受的瓶颈。

## 坑 17：`start.ps1` 报一堆语法错误，中文全是乱码

**现象**：运行 `start.ps1` 时 PowerShell 报
`Missing closing '}' in statement block`，且报错信息里的中文显示成 `鐪熷疄` 这样的乱码。

**原因**：Windows PowerShell **5.1** 对**没有 BOM** 的 `.ps1` 文件按系统 ANSI 代码页
（中文机器上是 GBK）解码。文件本身是 UTF-8，于是中文字符串全部变成乱码，
连引号配对都被破坏，解析器就报语法错。

**解决**：把 `start.ps1` 另存为 **UTF-8 with BOM**。

```powershell
# 一行修好（PowerShell 里执行）
$p = "start.ps1"
$t = [System.IO.File]::ReadAllText($p, [System.Text.UTF8Encoding]::new($false))
[System.IO.File]::WriteAllText($p, $t, [System.Text.UTF8Encoding]::new($true))
```

> PowerShell **7** 默认按 UTF-8 读脚本，不受影响；问题只出在 5.1。
> 本机未安装 pwsh 7，所以脚本按 5.1 兼容编写。

## 坑 18：启动脚本被 Python 的一条警告打断

**现象**：`start.ps1` 在调用 `python ...` 之后直接退出，没有继续往下走。

**原因**：PowerShell 5.1 会把外部程序写到 **stderr** 的每一行包装成 `NativeCommandError` 错误记录；
如果脚本开头设了 `$ErrorActionPreference = 'Stop'`，这条普通警告就会被当成终止性错误。

**解决**：启动脚本统一用 `$ErrorActionPreference = 'Continue'`，
关键步骤改成显式判断 `$LASTEXITCODE`，需要抛错的地方单独写 `-ErrorAction Stop`。
**不要**"顺手"把它改回 `Stop`。

## 坑 19：`python -c '...'` 里的双引号被 PowerShell 吃掉

**现象**：

```powershell
python -c 'import sys;print("%d.%d.%d"%sys.version_info[:3])'
# Python 报：SyntaxError: invalid syntax
#   实际收到的是：print(%d.%d.%d%sys.version_info[:3])
```

**原因**：PowerShell 5.1 在给外部程序拼装命令行时会重新加引号，
**PowerShell 单引号串内部的 `"` 会被吞掉**。

**解决**：传给外部程序的 Python 代码，一律写成「**PowerShell 双引号 + Python 单引号**」：

```powershell
python -c "import sys;print('%d.%d.%d'%sys.version_info[:3])"
```

或者干脆写成 `.py` 文件再执行（`tools/selfcheck.py` 就是这么来的）。

## 坑 20：`getaddrinfo failed` / `Max retries exceeded` —— 域名解析失败

**现象**：

```
API_REQUEST_FAILED：调用 DeepSeek 接口失败：ConnectionError: HTTPSConnectionPool(
host='api.deepseek.com', port=443): Max retries exceeded with url: /chat/completions
(Caused by NameResolutionError(...: Failed to resolve 'api.deepseek.com'
([Errno 11001] getaddrinfo failed)))
```

**这是什么**：`[Errno 11001] getaddrinfo failed` 是 Windows 的**域名解析不出来**。
跟你的代码、API Key、模型都没关系 —— 本机没能把 `api.deepseek.com` 变成 IP。
典型诱因：网络刚切换（Wi-Fi↔有线）、VPN 断开、运营商 DNS 抖动。**通常一两秒自愈。**

**现在的处理**：项目已内置**分层错误识别 + 自动重试**（`agent/llm.py`）：

* 这类失败被识别为 `NETWORK_DNS_FAILED`，标记为**可重试**；
* 自动做指数退避重试（默认 3 次，约 0.8s / 1.6s / 3.2s，带抖动）；
* Web 界面会实时提示「网络波动（NETWORK_DNS_FAILED），正在自动重试 2/4，1.6s 后重发…」；
* 如果重试仍失败，你刚才打的那句话会**自动回到输入框**，直接再点一次发送即可；
* 参数类错误（400 / 401 / 402 / 403）**不会重试**，立刻失败并说明原因——重试它们没有意义。

**还是不行怎么办**：先跑诊断，它会直接告诉你坏在哪一层：

```powershell
python tools/selfcheck.py --net
```

输出形如：

```
【网络分层诊断】
  [OK]   ① DNS 解析      api.deepseek.com → 112.49.40.58, 183.253.56.58 · 10 ms
  [WARN] ② TCP 443：1/3 个 IP 不可达   ← CDN 某个边缘节点不通，不影响使用
  [OK]   ③ TLS 握手      TLSv1.3 · 55 ms
  [OK]   ④ HTTPS 可达     GET https://api.deepseek.com → HTTP 401（未带 Key，属正常）
```

坏在第 ① 层（DNS）时的处理顺序：

1. 换网络 / 重连 Wi-Fi（最常见，立刻见效）
2. 关掉或切换 VPN / 代理
3. 刷新 DNS 缓存：`ipconfig /flushdns`
4. 手动改 DNS：`223.5.5.5`（阿里）或 `119.29.29.29`（腾讯）
5. 检查 `C:\Windows\System32\drivers\etc\hosts` 是否被人写过 `api.deepseek.com` 的静态映射

**错误码速查**（新分层）：

| 错误码 | 含义 | 自动重试 | 该怎么办 |
| --- | --- | --- | --- |
| `NETWORK_DNS_FAILED` | 域名解析失败 | ✅ | 见上面 1~5 |
| `NETWORK_UNREACHABLE` | TCP 连不上 / 代理拦截 | ✅ | 查防火墙、代理设置 |
| `NETWORK_TLS_FAILED` | 证书 / TLS 握手失败 | ❌ | 查系统时间、杀毒软件的自签名证书 |
| `API_TIMEOUT` | 连接或读取超时 | ✅ | 调大 `read_timeout` / `connect_timeout` |
| `API_RATE_LIMITED` | HTTP 429 被限流 | ✅ | 降低调用频率，等待即可 |
| `API_SERVER_ERROR` | HTTP 5xx | ✅ | 服务端问题，等一会儿 |
| `API_REQUEST_FAILED` | HTTP 400/401/402/403 | ❌ | 看 `hint`：模型名 / Key / 余额 / 权限 |
| `API_KEY_MISSING` | 没配 Key | ❌ | 配 `agent/.env.local` |

重试次数与退避可以在 `agent/config.py` 调：`max_retries`、`retry_backoff`。

## Q22：某一轮对话突然失败、回复是 0 字，报 `INTERNAL_ERROR`？

**先看错误码**。`INTERNAL_ERROR` 表示"框架内部出了没预料到的异常"，
它的 message 里带着异常类型和说明，例如：

```
INTERNAL_ERROR: JSONDecodeError: Invalid control character at: line 1 column 3001 (char 3000)
```

**已经修过的那一个**：工具结果超过 `MAX_TOOL_RESULT_CHARS = 6000` 字符时，
老的 `truncate()` 按纯文本从中间切一刀，切出来的不是合法 JSON，
`session.add_tool_result()` 再 `json.loads` 就抛异常，整轮直接失败、回复 0 字。
典型触发场景就是"档案记录攒得比较多了，让模型汇总一下"。

现在 `loop.truncate_tool_result()` 做**结构化裁剪**（解析 → 逐级瘦身 → 重新序列化），
保证回填给模型的永远是合法 JSON；`session._parse_for_log()` 作为第二道防线，
解析失败只降级存字符串，绝不外抛。详见
[10 · 真实 API 与端到端测试报告](10_真实API与端到端测试报告.md) 的 BUG-9。

**再遇到同类问题怎么查**：`run_turn` 会把所有异常兜底成 `INTERNAL_ERROR`，
拿不到堆栈。要定位就绕开兜底，直接调 `_run_steps`：

```python
import sys; sys.path.insert(0, "."); sys.path.insert(0, "src")
from agent.config import load_config
from agent.loop import Agent
from agent.session import SessionStore

ag = Agent(load_config(), store=SessionStore(load_config()))
s = ag.store.create(); s.add_user("你的问题", None); s.turns += 1
ag._run_steps(s, "t-probe", [], lambda *a, **k: None)   # 异常会带完整 traceback 抛出
```

**顺带**：这类"框架内部异常"在 Web 界面上会连同 `hint` 一起显示；
如果 `info` 里有 `retryable=True`，说明是网络类故障，系统已经自动重试过了。

## Q21：接了真实 API Key 之后，`verify_agent.py` 反而不全过了？

**原因**：该脚本调用 `load_config()`，而 `load_config` 在"有 Key"时会自动选真实模型客户端。
于是这套**本该可复现的骨架自查**悄悄变成了"真实模型行为测试"，
两条依赖具体措辞或固定工具序列的断言就会随模型的自由发挥而失败。

**现状**：已修复。`verify_agent.py` **默认强制 `cfg.offline = True`**（并在输出里标明当前模式），
要跑真实模型请显式加 `--live`。

**分工**：

| 脚本 | 管什么 | 可复现 |
| --- | --- | --- |
| `tools/verify_agent.py` | 智能体**骨架**：工具注册、门禁、错误码、会话、Web 路由 | 是（离线替身） |
| `tools/e2e_test.py` | **真实模型**行为：工具链、多轮会话、拒识话术 | 否（有随机性，但实测 13 轮全部符合预期） |

## 排错流程速查

```
问题 → 先看什么？
─────────────────────────────────────────────
指标不对      → ① 推理精度(amp) ② TTA 设置 ③ 样本顺序 ④ 划分(train/val)
精度太低      → ① val_loss 是否 >10（学习率）② 预训练权重是否加载 ③ epochs 够不够
跑不起来      → ① 文件/模型路径 ② 配置 JSON 是否合法 ③ 权重是否本地存在
结果不稳定    → ① 是否开了 EMA ② 是否只跑了一次（<0.005 的差异可能是噪声）
提交被拒      → 跑 python src/verify_submission.py，按 FAIL 逐条修
启动脚本乱码  → .ps1 必须 UTF-8 with BOM（坑 17）
启动脚本中断  → 不要用 $ErrorActionPreference='Stop'（坑 18）
getaddrinfo failed → 瞬时 DNS 故障，系统会自动重试；持续失败跑 python tools/selfcheck.py --net（坑 20）
模型不调工具  → ① 工具 description 是否说清"何时调用" ② 参数 Schema 是否严格 ③ 看 event log
拒识不生效    → ① t 是否由验证集扫出来 ② 工具结果的 decision.action 是否被模型采纳
```
