1. 根目录文件

1.1 classes.txt ★ 必须提交

项目 内容
大小 250 字节
编码 UTF-8，无 BOM
行数 恰好 50 行（末尾有一个换行符，所以 count("\n") == 50）
每行内容 一个四位数字的车型 ID，保留前导零，如 0003
顺序 按 ID 升序
是否含 unknown 不含。unknown 是模型的第 51 类，不写入本文件
作用 本组类别登记、模型标签映射、教师后续测试的唯一类别清单

前 5 行实际内容：

0003
0019
0025
0035
0061

生成的唯一途径：python src/select_classes.py（读 configs/selection.json）。 不要手工编辑——一旦手改，classes.txt 与 configs/class_map.json 会不一致， 导致模型输出索引与类别 ID 错位，verify_submission.py 会立刻报错。

什么时候重新生成：改变选类方案后（改 configs/selection.json → 重跑 select_classes.py → 重跑 prepare_data.py → 重新训练）。

1.2 predictions.csv ★ 必须提交

项目 内容
大小 约 72 KB
编码 UTF-8，无 BOM
表头 固定为 image_id,predicted_label,confidence
记录数 2,422（与 data/val 图片数一致）
image_id 包含扩展名的图片文件名，如 0003_0009.jpg；无重复
predicted_label classes.txt 中的四位车型 ID（保留前导零）或小写 unknown
confidence 0~1 的有效数值，保留 6 位小数

实际内容示例：

image_id,predicted_label,confidence
0003_0009.jpg,0003,0.962251
0003_0016.jpg,0003,0.933231
...
0984_0359.jpg,unknown,0.303768

生成的途径： - src/predict_batch.py —— 单模型，对 --input-dir 或 --split 推理； - src/finalize.py —— 集成模型，比选后选冠军再生成（本项目最终用的是这条路径）。

当前状态：对本地 data/val 生成的演练版本。教师指定的测试目录下发后需要重跑（见文档 01 第 8.1 节）。

1.3 predictions.meta.json

记录"这份 predictions.csv 到底是用什么配置生成的"，用于事后追溯与自证。

{
  "champion": "improved_resnet18_224+improved_resnet50_224",
  "members": ["improved_resnet18_224", "improved_resnet50_224"],
  "prior_adjust_tau": 0.05,
  "unknown_threshold": 0.25,
  "tta_hflip": true,
  "val_macro_f1": 0.96038,
  "calibration_source": "outputs/reports/final_model_choice.json（由验证集 Macro-F1 选出）"
}
字段 含义
champion 生成这份结果的模型（可以是单模型名或 A+B 形式的集成）
members 集成的成员列表（单模型时只有一个元素）
prior_adjust_tau 先验校正强度 τ（见文档 06）
unknown_threshold 拒识阈值 t（见文档 06）
tta_hflip 是否启用了水平翻转 TTA
val_macro_f1 该配置在验证集上的 Macro-F1
calibration_source τ 与 t 的来源文件

作用：当有人质疑"你的 0.9604 是怎么来的"时，打开这个文件就能看到完整的决策链。 能不能删：可以，但会失去可追溯性，建议保留。

2. configs/ — 配置层（10 个文件）

配置层分为三组：教师给的、我生成的数据约定、训练超参。

2.1 教师给的（只读，不要改）

class_info.json

  • 来源：从数据集压缩包的 cls_info/class_info.json 复制而来。
  • 内容：827 个类别的列表，每条 4 个字段：
{
  "id": "0000",
  "name_from_new": "江铃_凯运",
  "name_from_old": "江铃_凯运==JMC_Kaiyun",
  "type_info": "卡车####轻卡==Truck####Light Truck"
}
字段 含义
id 四位类别 ID，classes.txt 与 predictions.csv 用的就是它
name_from_new 规定使用的标签名（车型名称展示、查询结果、报告中的类别命名）
name_from_old 旧版名称，格式为 中文名==英文名
type_info 类型信息，格式为 中文大类####中文细分==英文大类####英文细分
  • 什么时候用：选类、生成类别映射、报告中写车型名称时。
  • 不能删：select_classes.py 与 verify_submission.py 都依赖它。

2.2 我生成的数据约定（4 个）

selection.json — 选类方案（改选类就改这里）

这是人工策划的文件，不是脚本生成的。结构：

{
  "project": { "name": "...", "theme": "...", "goal": "..." },
  "selection_principles": ["P1 ...", "P2 ...", ...],
  "classes": [
    { "id": "0632", "group": "轿车", "reason": "德系豪华中大型轿车标杆，样本量全库最大..." },
    ...
  ],
  "unknown_plan": {
    "hard_negative_per_brand": 1,
    "other_brand_classes": 64,
    "min_train_images": 80,
    "train_per_source": 20,
    "val_per_source": 6,
    "note": "..."
  }
}
字段 作用
project 项目名称、选题方向、一句话目标（会写进选类报告）
selection_principles 6 条选类原则（P1 主题契合 / P2 车身类型覆盖 / P3 品牌多样性 / P4 单车系单一代表 / P5 样本充足 / P6 造型辨识度）
classes[] 50 条，每条含 id、group（车身大类）、reason（选择理由，报告直接引用）
unknown_plan.hard_negative_per_brand 每个品牌取几个"兄弟车型"作为 unknown 硬负样本（本项目 1）
unknown_plan.other_brand_classes 其他品牌取多少个 unknown 来源类别（本项目 64）
unknown_plan.min_train_images 来源类别的最低训练样本量门槛（本项目 80）
unknown_plan.train_per_source 每个来源类别取多少张训练图（本项目 20）
unknown_plan.val_per_source 每个来源类别取多少张验证图（本项目 6）

class_map.json — 全项目最重要的映射文件

{
  "note": "索引 0~49 按 classes.txt 行顺序对应 50 个目标车型；索引 50 对应 unknown。训练/保存/Web 推理/批量推理共用本映射。",
  "index_to_id":   { "0": "0003", "1": "0019", ..., "49": "0987" },
  "index_to_name": { "0": "宇通客车_宇通T7", "1": "吉利汽车_星瑞", ... },
  "index_to_group":{ "0": "轻客", "1": "轿车", ... },
  "id_to_index":   { "0003": 0, "0019": 1, ... },
  "unknown_index": 50,
  "unknown_label": "unknown",
  "num_classes": 51
}
字段 类型 含义 谁在用
index_to_id dict[str,int→str] 模型输出下标 → 四位车型 ID 推理、写 predictions.csv
index_to_name dict 下标 → 车型中文名 报告、Web 展示
index_to_group dict 下标 → 车身大类 按大类检索（任务二）
id_to_index dict[str→int] 车型 ID → 下标（反向查表） CarDataset 推断标签
unknown_index int 固定为 50 所有未知类判断
unknown_label str 固定为 "unknown" 写 predictions.csv
num_classes int 固定为 51 模型分类头维度

为什么它这么关键：训练时模型输出的第 7 个位置的权重，到底代表"大众_朗逸"还是"保时捷 718"？ 全靠这一份文件。它随 checkpoint 一起保存，所以加载旧模型不会错位。

2.3 训练超参（5 个）

文件 run_name 骨干 输入 epochs 状态
train_baseline.json baseline_resnet18_160 resnet18 160 12 ✅ 已跑（实验 A）
train_weighted.json weighted_resnet18_160 resnet18 160 12 ✅ 已跑（实验 B）
train_improved.json improved_resnet18_224 resnet18 224 18 ✅ 已跑（实验 C1）
train_improved_r50.json improved_resnet50_224 resnet50 224 14 ✅ 已跑（实验 C2）

train_moderate.json 是干什么的：当时担心"强增强对 7.5k 规模的数据集过度正则化"， 准备了一个中等强度增强的对照配方（不用 RandAugment / MixUp，只用缩放裁剪 + 颜色抖动 + 随机擦除）。 后来 C1 在 epoch 6 反超基线并最终领先 0.10，证明担心是多余的，所以这个配置没跑。 保留它作为可选的对照，要跑就跑：

python src/train.py --config configs/train_moderate.json

4. tools/、scripts/ 与根目录启动脚本

start.ps1（项目根目录）

任务二三的一键启动脚本：找 Python → 确认 API Key → 环境自检 → 起服务 → 开浏览器。 参数见 05 · 脚本与命令手册 第 9.1 节。

⚠️ 必须以 UTF-8 with BOM 保存。Windows PowerShell 5.1 会把无 BOM 的 .ps1 当系统 ANSI（GBK）解码，中文会变乱码并直接语法报错。 ⚠️ 内部不能用 $ErrorActionPreference='Stop'：PS 5.1 会把 python.exe 写到 stderr 的每一行 当成终止性错误。脚本统一用 Continue + 显式判断 $LASTEXITCODE。

start.bat（项目根目录）

双击入口（内容全为 ASCII，不受编码影响）。自动挑 PowerShell （pwsh → Program Files\PowerShell\7 → WindowsApps → 系统自带 5.1）， 把命令行参数原样转给 start.ps1，结束后 pause 以免窗口一闪而过。

tools/selfcheck.py

启动前环境自检，37 项：Python 版本、必需/可选依赖、API Key 来源与脱敏、 .env.local 是否仍被 gitignore、交付文件存在性与格式（classes.txt 50 行 4 位升序无 BOM 不含 unknown、 predictions.csv 表头）、视觉权重是否齐全、目录可写、端口占用、磁盘空间、工具装配（≥1 视觉 + ≥2 其他）。 --api 加做一次真实 API 调用，--vision 加做一次真实视觉推理，--all 全量，--json 供脚本解析。 退出码 0 = 无 FAIL（可有 WARN），1 = 有 FAIL。

tools/e2e_test.py

任务二三的端到端测试，两段可单独跑： 阶段 A（不经过模型，约 7 s，20 项）直接调 ToolRegistry.execute，验证参数校验、前置门禁、 错误码与拒识分支；阶段 B（真实 DeepSeek API，约 40 s，33 项）跑 8 个对话场景共 13 轮， 验证单轮 3 工具串联、多轮会话沿用上文、unknown 拒识、异常反馈。 --stage A|B、--only S3,S5、--offline、--cleanup、--json。

tools/verify_agent.py

任务二三提交前自查，101 项，逐条对照任务书第五、六节： 工具注册与 Schema、执行流水线、错误码、会话与事件日志、连续工具调用、多轮对话、 unknown 处理、Web 路由与前端要素、界面能力（会话管理 / 设置 / 联网搜索 / 浏览器抓取）， 以及"提交材料不得包含真实 API Key"的合规检查。 默认走离线替身以保证结果可复现，--live 才切到真实模型（真实模型的行为测试由 e2e_test.py 负责）。

tools/verify_browser.py

专门验证真实浏览器抓取链路，21 项：工具门控、参数校验、真实打开 JS 渲染站点 （汽车之家轩逸页，应能读到「厂商指导价」）、会话复用、浏览器不可用时的 HTTP 降级、 工具卡摘要、以及真实模型的多轮联网（搜索 → 打开 → 综合）。需要机器上能启动 Chromium。

tools/build_docs_html.py

把 docs/ 下的全部 Markdown 生成 HTML：一个自带侧边栏/目录/搜索的单文件版 （docs/识车档案_CarDex_说明文档.html），以及 docs/html/ 下的分页版。 两者都会把文档之间的 .md 链接改写成站内可跳转的目标，不会出现点开是原始 Markdown 的情况。 用法：python tools/build_docs_html.py。需要 markdown 与 pygments。

tools/build_car_profiles.py

从 configs/class_info.json 构建智能体用的车型资料库 agent/data/car_profiles.json。 不编造参数：数据集只提供类别 ID 与车型名，所以档案里只有品牌、车身大类/细分、简介与看点， data_source 字段记录了每条的来源。

tools/derive_confidence_threshold.py

在验证集上做选择性预测分析，推导"低置信度提示阈值"display_confidence_threshold（默认 0.70）， 写入 agent/data/confidence_threshold.json。注意它只影响智能体的措辞与交互， 不影响模型输出（真正的拒识由 τ 与 t 决定）。

scripts/run_after_c2.ps1

一次性运维脚本：等待 C2（ResNet50）训练完成后自动执行 "评估 → 标定 → 比选 → 生成 predictions.csv → 汇总 → 自查"的整条链。 属于历史遗留（已经手动执行过了），保留作为"无人值守收尾"的参考。

5. data/ — 抽取出的图片

data/
├── train/
│   ├── 0003/ … 0987/      ← 50 个目标车型目录（共 5,534 张）
│   └── unknown/           ← 组外来源类别（1,960 张）
└── val/
    ├── 0003/ … 0987/      ← 50 个目标车型目录（共 1,834 张）
    └── unknown/           ← 组外来源类别（588 张）
项目 数值
图片总数 9,916（train 7,494 + val 2,422）
占用磁盘 约 640 MB
格式 全部 JPG
命名 {类别ID}_{序号}.jpg，例如 0003_0009.jpg

目录名规则（CarDataset 就是靠它推断标签的）： - 目录名是四位数字 → 查 class_map.json 的 id_to_index，得到 0~49 的索引； - 目录名是 unknown → 固定给索引 50； - 其他目录名 → 忽略（跳过）。

能不能删：能，但必须能用 python src/prepare_data.py 重新抽出来 （前提是教师数据集 zip 还在）。重新抽约 10 秒。

为什么 train / val 的文件名不重叠：因为两批图来自压缩包内不同的官方划分 （train/<类>/ 与 val/<类>/），且 unknown 也是按来源类别的 train 与 val 分别抽取的。 verify_submission.py 会检查文件名重叠数必须为 0。

6. outputs/ — 产物层

6.1 outputs/checkpoints/<run>/ — 模型文件

任务书明确要求不随作业提交，只在本地保存用于系统运行。

文件 内容 什么时候用
best.pt 验证集 Macro-F1 最高的那一轮 评估、推理、集成、生成 predictions.csv
last.pt 最后一轮 想继续训练（fine-tune）时作为起点
epoch_04.pt / epoch_08.pt / … 中期 checkpoint，每 checkpoint_interval 轮存一个 任务书 4.2.3 要求保留；也可用于比较不同轮次的泛化能力

每个 .pt 里打包了什么（torch.load 后是一个 dict）：

键 含义
model_state 模型权重（若启用 EMA，这里存的是 EMA 平滑后的权重）
arch 骨干网络名，如 resnet18
num_classes 51
image_size 输入分辨率，如 224
class_map 完整的类别映射（与 configs/class_map.json 一致）
label_names 长度 51 的标签名列表，最后一个是 unknown
preprocess 预处理参数：mean / std / eval_resize / eval_crop / interpolation
train_config 完整的训练配置（相当于把对应的 configs/train_*.json 也存了一份）
epoch 该 checkpoint 对应的轮次
val_macro_f1 该轮次在验证集上的 Macro-F1
ema 布尔值，权重是否经过 EMA

因为这个 dict 自包含，重新加载时不需要任何外部文件—— 这就是 verify_reload.py 能跨进程复现 240/240 的原因。

各实验的 checkpoint 数量：

run 数量 文件
baseline_resnet18_160 5 best / last / epoch_04 / epoch_08 / epoch_12
weighted_resnet18_160 5 best / last / epoch_04 / epoch_08 / epoch_12
improved_resnet18_224 8 best / last / epoch_03/06/09/12/15/18
improved_resnet50_224 6 best / last / epoch_03/06/09/12

单个 best.pt 大小：resnet18 约 43 MB，resnet50 约 95 MB。

文件 内容 报告中的用途

8. 哪些文件能删、哪些绝对不能删

❌ 绝对不能删（删了要重跑训练或无法提交）

文件 原因
classes.txt 提交物，且是标签映射的依据
predictions.csv 提交物
configs/class_map.json 所有推理都依赖它
configs/class_info.json 车型名称的唯一来源

src/cardex/ 全部脚本依赖

⚠️ 删了要重算，但可恢复

文件 恢复方式
data/（9916 张，约 640 MB） python src/prepare_data.py（约 10 秒）
outputs/runs/*/logits_val_tta.npz 重跑 calibrate.py 或 finalize.py（约 2 分钟）
outputs/runs/finalize_cache/ 重跑 finalize.py（约 4 分钟）
outputs/reports/*.png python src/make_reports.py / data_analysis.py / visualize_errors.py
outputs/reports/experiment_comparison.md python src/make_reports.py

_checklibs.py 临时检查脚本
数据集.zip、数据集/ 不是本项目生成的，占约 13 GB；prepare_data.py 读的是 Downloads 下的原件
outputs/runs/ensemble/、ensemble_c1_a/ 只是对照实验的记录，结论已写进报告
