1. 任务一交出了什么

2. 视觉分类工具（classify_car）的实现

2.1 最简用法（推荐，用最终交付的集成模型）

import sys
sys.path.insert(0, "src")                      # 或把 src 加入 PYTHONPATH

from cardex.inference import CarEnsemble

# 只构造一次，全局复用（模型加载约 3 秒，不要每次调用都构造）
_classifier = CarEnsemble(
    ["outputs/checkpoints/improved_resnet18_224/best.pt",
     "outputs/checkpoints/improved_resnet50_224/best.pt"],
    tta_hflip=True,
    prior_adjust_tau=0.05,        # 来自 final_model_choice.json
    unknown_threshold=0.25,       # 来自 final_model_choice.json
)

def classify_car(image_path: str) -> dict:
    """视觉分类工具：识别图片中的车型。"""
    return _classifier.predict_path(image_path, top_k=5)

返回值：

{
    "label_id": "0975",              # 四位车型 ID，或 "unknown"
    "label_name": "日产_轩逸",         # 中文车型名（可直接展示）
    "index": 48,                     # 0~50 的类别索引
    "confidence": 0.9857,            # 0~1
    "is_unknown": False,             # ★ 低置信度处理直接看这个
    "top_k": [
        {"label_id": "0975", "label_name": "日产_轩逸", "index": 48, "probability": 0.9857},
        {"label_id": "unknown", "label_name": "unknown", "index": 50, "probability": 0.0071},
        ...
    ],
    "image_path": "C:/uploads/xxx.jpg",
    "image_id": "xxx.jpg"
}

2.2 单模型用法（更轻，推理快一倍）

from cardex.inference import CarClassifier
clf = CarClassifier(
    "outputs/checkpoints/improved_resnet50_224/best.pt",
    tta_hflip=True,
    prior_adjust_tau=-0.20,      # 注意：不同模型的最优 τ 不同！见下表
    unknown_threshold=0.20,
)
r = clf.predict_path("图片.jpg", top_k=5)

⚠️ 每个模型的最优标定参数不同：

模型 τ t 验证集 Macro-F1
C1 improved_resnet18_224 +0.10 0.20 0.9510
C2 improved_resnet50_224 −0.20 0.20 0.9592
C3 集成（推荐） +0.05 0.25 0.9604

用错 τ 会掉分。参数就在 outputs/runs/<run>/calibration.json 的 recommended 字段里， 或 outputs/reports/final_model_choice.json 的 champion.best 里。

2.3 内存中的 PIL Image（Web 上传流）

Web 后端通常拿到的是内存中的图片，不是磁盘路径。用 predict_image：

from PIL import Image
img = Image.open(io.BytesIO(uploaded_bytes))
r = _classifier.predict_path  # ❌ 不能用，它要路径
r = _classifier.members[0].predict_image(img, top_k=5)   # 只能单模型

集成模型的 predict_image 目前没有直接暴露（因为 predict_batch 需要列表）。 推荐做法：上传后先存成临时文件，再调用 predict_path：

import tempfile, os
fd, tmp = tempfile.mkstemp(suffix=".jpg"); os.close(fd)
with open(tmp, "wb") as f:
    f.write(uploaded_bytes)
try:
    r = _classifier.predict_path(tmp, top_k=5)
finally:
    os.remove(tmp)

或者直接给 CarEnsemble 加一个 predict_image（几行代码，见 2.4）。

2.4 想给 CarEnsemble 加单图方法

# 在 src/cardex/inference.py 的 CarEnsemble 里加：
@torch.no_grad()
def predict_image(self, image, top_k=5):
    pred = self.predict_batch([image])[0]
    return pred

3. 任务书对智能体的要求 vs 任务一提供的支撑

任务书第五节的关键要求，以及任务一已经准备好的部分：

任务书要求（5.1~5.5） 任务一已提供的支撑
"视觉识别必须通过智能体工具调用执行" 提供 classify_car 的完整实现（2.1 节）

4. 业务数据从哪来

任务二需要"车型档案查询"这类工具，数据来源建议如下。

4.1 直接可用：类别映射

// configs/class_map.json
"index_to_id":    { "0": "0003", ... },
"index_to_name":  { "0": "宇通客车_宇通T7", ... },
"index_to_group": { "0": "轻客", ... },        // ★ 车身大类，适合做筛选条件
"id_to_index":    { "0003": 0, ... }

index_to_group 的取值只有 6 种：轿车 / SUV / MPV / 跑车 / 微面 / 轻客。 可以直接支持"帮我找几款 SUV"这样的自然语言筛选。

4.2 需要自己补：车型详细档案

教师数据集只提供类别 ID 与名称，没有排量、价格、座位数等参数。 所以"车型档案"需要自己构建，建议：

来源 内容 说明
outputs/reports/selection_report.txt 50 类的车型名、品牌、车身大类、train/val 样本量 可直接作为初始条目
configs/class_info.json 的 type_info 中文大类 + 细分（如 SUV####紧凑型） 补充"级别"字段
自行整理 座位数、续航、车身尺寸、看点 可以手写或让大模型生成后人工校对

⚠️ 合规提醒：任务书要求"工具应真实执行对应操作，不能用固定文本或伪造结果代替功能"。 如果车型介绍是预先写死的，需要在报告里说明数据来源，不要声称是实时查询。

建议把整理好的档案存成 JSON 或 SQLite，用"车型档案查询工具"去读—— 这样才是"真实的业务操作"，而不是把介绍写在 prompt 里。

4.3 建议的数据库表结构

-- 车型档案
CREATE TABLE car_profile (
    car_id      TEXT PRIMARY KEY,   -- 四位 ID，与 class_map.json 一致
    name        TEXT NOT NULL,      -- 中文名
    brand       TEXT NOT NULL,      -- 品牌
    body_group  TEXT NOT NULL,      -- 车身大类（轿车/SUV/...）
    body_detail TEXT,               -- 细分（紧凑型 SUV 等）
    seats       INTEGER,
    intro       TEXT,               -- 介绍文案
    source      TEXT                -- 数据来源说明（合规要求）
);

-- 个人收藏 / 看车记录
CREATE TABLE car_record (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id  TEXT NOT NULL,      -- 会话 ID（多轮对话用）
    car_id      TEXT NOT NULL,      -- 四位 ID 或 "unknown"
    confidence  REAL,
    image_path  TEXT,
    note        TEXT,
    created_at  TEXT NOT NULL
);

5. 低置信度与异常的推荐处理流程

任务书 5.5 节要求处理低置信度、unknown、图片读取失败、API 失败、工具失败。 结合任务一的实测结论，建议这样处理：

def handle_prediction(r: dict) -> dict:
    """把视觉模型的输出翻译成给智能体的决策建议。"""
    if r["is_unknown"]:
        # 情况 1：模型明确说"不认识"
        return {
            "status": "unknown",
            "message": "未识别为本组支持的 50 款车型之一。",
            "hint": "如果你想记录这辆车，可以手动填写车型，或换一张更清晰的照片。",
            "top_k": r["top_k"],           # 展示候选，但不要当作确定答案
        }
    if r["confidence"] < 0.60:
        # 情况 2：认得，但不太确定
        return {
            "status": "low_confidence",
            "message": f"可能是 {r['label_name']}，但置信度只有 {r['confidence']:.0%}。",
            "hint": "请确认是否是该车型，或重新拍摄一张更清晰的照片。",
            "top_k": r["top_k"],           # ★ 必须展示 Top-K 让用户选
        }
    # 情况 3：高置信度
    return {"status": "ok", "label_id": r["label_id"], "label_name": r["label_name"]}

三条重要提醒（都来自任务一的实测结论）：

  1. 阈值 0.60 是"提示阈值"，不是"提升精度的手段"。 本任务的主要错误是高置信度错误（模型以 0.99 的置信度认错）， 阈值只能拦"不自信"的样本。任务书也明确说"低置信度处理不能替代 unknown 类别的训练"。
  2. is_unknown 优先级高于 confidence。 unknown 的 confidence 可能很高（模型很确定这是不认识的车）， 也可能很低。先看 is_unknown，再看 confidence。
  3. 不要把 top_k 当作"备选答案"直接选一个。 如果模型最高分都是 unknown，说明它认为这不是已知车型， 不应该从 Top-2 里硬挑一个返回给用户。

6. 多轮对话中"沿用上一轮图片与识别结果"

任务书 5.4 节要求：

第一轮：用户上传图片，询问"这是什么？" → 智能体返回识别结果。 第二轮：用户输入"帮我记录下来。" → 智能体利用上一轮的识别结果完成记录，无需重新上传图片。

实现建议：在 Session 状态里缓存最近一次的识别结果：

session_state = {
    "session_id": "abc123",
    "last_image_path": "/uploads/abc123.jpg",
    "last_prediction": {          # 上一步 classify_car 的完整返回值
        "label_id": "0975",
        "label_name": "日产_轩逸",
        "confidence": 0.9857,
        "is_unknown": False,
        "top_k": [...],
    },
}

关键设计：让"记录"工具（如 add_car_record）接受 car_id 参数而不是图片路径。 这样智能体在第二轮可以直接把 session_state["last_prediction"]["label_id"] 传进去， 不需要重新调用 classify_car——这既是"沿用上下文"，也避免了重复推理。

7. 连续调用 3 个工具的推荐任务流

任务书 5.3 节要求"至少一个连续调用 3 个或以上工具的完整任务"。 本项目选题（私人车型资料库）的自然流程：

用户："这是什么车？介绍一下，然后加进我的收藏。"

Agent ① classify_car(image_path)                    → 返回 0975 / 日产_轩逸 / 0.986
Agent ② query_car_info(car_id="0975")               → 返回车型档案（品牌、车身、看点）
Agent ③ add_car_record(car_id="0975", note="...")   → 写入个人看车档案，返回记录 ID
Agent 汇总结果 → 回答用户

再加一个更有"个人知识库"味道的：

用户："把那辆轩逸的档案调出来给我看看。"
Agent ① search_my_records(keyword="轩逸")            → 找到记录
Agent ② query_car_info(car_id="0975")               → 取档案
Agent ③ （可选）update_record_note(...)             → 补充备注

工具清单建议（≥3 个，其中 1 个是视觉的）：

工具 输入 输出 实现依据
classify_car image_path 类别 ID / 名称 / confidence / Top-K / is_unknown 任务一已实现（CarEnsemble）
query_car_info car_id 车型档案（品牌、车身大类、细分、介绍） 需自建档案库
add_car_record car_id, note, image_path 记录 ID 需自建数据库
search_my_records keyword / body_group 记录列表 需自建数据库
list_supported_cars body_group（可选） 50 类的清单 直接读 class_map.json

8. 工程注意事项

8.1 不要重复构造分类器

模型加载约 3 秒（resnet50 更久）。全局构造一次，复用同一个实例：

# ✅ 正确：模块级单例
_classifier = None
def get_classifier():
    global _classifier
    if _classifier is None:
        _classifier = CarEnsemble([...], ...)
    return _classifier

8.2 线程安全

PyTorch 模型的推理（torch.no_grad() 下）是只读操作，多线程调用一般安全， 但 Python 的 GIL 会让推理串行化。 如果 Web 框架是多 worker 的（如 gunicorn 多进程），每个进程各持有一份模型副本， 内存占用会翻倍——这时可以改用单模型（C2）以减少内存。

8.3 路径

cardex.paths 里的路径都是相对项目根目录的绝对路径（基于 __file__ 推导）， 所以无论从哪个工作目录启动都能正确找到文件：

from cardex import paths
print(paths.CKPT_DIR)     # E:\...\car-kb-agent\outputs\checkpoints

8.4 依赖

任务二/三只需要 src/cardex/ 里的 4 个模块：

paths.py      # 路径与映射
data.py       # CarDataset + build_transform（inference 会用到 transform）
models.py     # build_model
engine.py     # load_model_from_checkpoint
inference.py  # CarClassifier / CarEnsemble
utils.py      # configure_threads
metrics.py    # 可选

不需要 train.py / finalize.py 等训练侧脚本。

8.5 提交合规

任务书要求：

API Key 通过环境变量或本地配置管理，不写入公开代码、报告或截图；提交配置示例时使用占位符。

建议：

import os

不要把 Key 写进 .py、.md、.json 或截图里。

9. 已实测的性能数字（供 Web 端预估）

操作 耗时 说明
加载 C1 单模型（resnet18@224） 约 1~2 秒 首次
加载 C2 单模型（resnet50@224） 约 2~3 秒 首次
加载 C3 集成（两个模型） 约 3~5 秒 首次
单张识别（C1，无 TTA） 约 0.5 秒 224 输入
单张识别（C1，开 TTA） 约 0.9 秒 推理翻倍
单张识别（C3 集成 + TTA） 约 2 秒 两个模型 × 两次前向
批量 2,422 张（C1 + TTA） 约 130 秒 18.6 张/秒
批量 2,422 张（C3 + TTA） 约 320 秒 7.6 张/秒

给 Web 端的建议： - 交互式单图识别用 C1 + TTA（约 1 秒，Macro-F1 0.9510）即可，体验更好； - 需要最高精度的批量任务用 C3（约 320 秒/2422 张）； - 若服务器内存紧张，只加载 C2（单个 resnet50，Macro-F1 0.9592）。

注意：以上都是纯 CPU 数字。有 GPU 时会快很多。
