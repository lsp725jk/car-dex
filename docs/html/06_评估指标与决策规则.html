06 评估指标与决策规则

本文档解释本项目用到的每一个指标与每一条决策规则：定义、公式、怎么算、 为什么这么算、以及它们之间此消彼长的关系。

1. 唯一评分指标：51 类等权 Macro-F1

1.1 任务书的规定

任务书 4.3 节原文：

视觉模型最终效果评分以 Macro-F1 为唯一指标，计算范围为本组所选的 50 个车型与 unknown，共 51 类。 F1 = 2 × TP / (2 × TP + FP + FN) Macro-F1 = (F1_1 + F1_2 + … + F1_51) / 51 其中 TP、FP、FN 分别表示该类预测正确、误报和漏报的图片数；分母为 0 时，该类 F1 按 0 处理。 unknown 与每个目标车型具有相同的类别权重，作为第 51 类参与最终评分，不从评分数据中排除。 将目标车型误判为 unknown、将未知车型误判为目标车型，均计入相应类别的错误。

1.2 逐类 F1 怎么算

对第 c 类：

符号 含义 在本任务中的具体含义
TP_c 该类预测正确的图片数 真实是 c 且预测是 c
FP_c 该类的误报数 真实不是 c 但预测是 c
FN_c 该类的漏报数 真实是 c 但预测不是 c 
Precision_c = TP_c / (TP_c + FP_c)      查准率：判为该类的里面有多少是真货
Recall_c    = TP_c / (TP_c + FN_c)      查全率：该类真实样本里有多少被找出来
F1_c        = 2 × P_c × R_c / (P_c + R_c) = 2·TP_c / (2·TP_c + FP_c + FN_c)

等价形式（任务书给的式子）：F1 = 2 × TP / (2 × TP + FP + FN)。

1.3 为什么是"等权"平均，这带来了什么后果

Macro-F1 = (F1_1 + … + F1_51) / 51 —— 每个类别占 1/51 ≈ 1.96%，与样本量无关。

后果一：任何一个"崩掉"的类别都会拖累总分。 基线模型的日产_轩逸 F1 只有 0.618，单这一项就比满分少了 0.382/51 ≈ 0.0075 的总分。 如果把它的 F1 提到 0.866（本项目最终水平），总分立刻多出 0.0049。

后果二：样本量大的类别没有额外话语权。 unknown 有 588 张验证图（占 24.3%），但在 Macro-F1 里和只有 26 张的丰田_埃尔法权重完全一样。 所以"把 unknown 全猜对、其他类随便"是没用的策略。

后果三：Accuracy 会骗人。 本项目的 unknown 占 24.3%，如果把所有图都猜成"某个高概率目标车型"， Accuracy 依然不低，但 unknown 那一类的 F1 会直接归零。所以必须看 Macro-F1。

1.4 分母为 0 的处理

按任务书：某类的 TP+FP+FN = 0（即该类在验证集里没有任何样本，且从未被预测成该类）时， 该类 F1 记 0。

代码实现（src/cardex/metrics.py）：

macro_f1 = f1_score(y_true, y_pred, labels=list(range(51)), average="macro", zero_division=0)

zero_division=0 保证与任务书一致。 本项目不会触发这种情况：50 个目标车型在验证集各有 26~62 张， unknown 有 588 张，任何一类都不可能为空。

1.5 本项目的 Macro-F1 演进

阶段 模型 Macro-F1 说明
基线 ResNet18@160 轻量增强 0.8475 训练集准确率 99.6%，严重过拟合
改进 ResNet18@224 强增强+EMA+MixUp+TTA 0.9482 验证集准确率反超训练集
更强 ResNet50@224 同配方 0.9550 容量收益边际递减
最终 C1+C2 集成 + 决策标定 0.9604 当前交付

2. 辅助指标

这些不是评分依据，但用于诊断问题。

2.1 Accuracy（整体准确率）

Accuracy = 预测正确的图片数 / 总图片数

本项目最终值：0.9496。

为什么不能只看它：它是按样本加权的，会被大类主导。 如果模型把所有图都预测成出现频率最高的类，Accuracy 也不会是 0，但 Macro-F1 会很难看。

2.2 unknown 检出率（unknown detection rate / recall）

unknown_detection_rate = 真实是 unknown 且被正确判为 unknown 的张数
                       / 真实是 unknown 的总张数

本项目最终值：0.9286（基线 0.8197）。

含义：模型"敢不敢说不认识"。 太低 → 用户拍了一辆你没选的车，模型硬报一个车型，后续业务会写错数据。

2.3 已知类误拒率（known false-reject rate）

known_false_reject_rate = 真实是已知车型但被判为 unknown 的张数
                        / 真实是已知车型的总张数

本项目最终值：0.0344（基线 0.1031）。

含义：模型"会不会错杀自己认识的车型"。 太高 → 用户明明认识的车，系统说"不认识"，体验很差。

2.4 两者的此消彼长关系（核心）

这两个指标是一对矛盾：

                      往"更敢说 unknown"调
    unknown 检出率 ↑↑         已知类误拒率 ↑↑
    ← ────────────────────────────────────── →
    unknown 阈值 ↓            未知阈值 ↑
                      往"更敢认车型"调

两个旋钮控制这个平衡：

  1. 先验校正强度 τ —— 改的是 logits；
  2. 拒识阈值 t —— 改的是最终决策。

本项目的实测权衡曲线（C2 模型）：

τ Macro-F1 unknown 检出率 已知类误拒率
−1.00 0.9096 0.983 0.141
−0.50 0.9496 0.966 0.065
−0.20 0.9592 0.939 0.036
0.00 0.9550 0.896 0.024
+0.30 0.9486 0.835 0.016
+1.00 0.9031 0.515 0.003

可以看到：τ 越小（越倾向 unknown），检出率越高、误拒率也越高， 而 Macro-F1 在 τ=−0.20 处达到峰值——这就是"平衡点"。

3. 决策规则：τ 与拒识阈值

完整推理流程（src/cardex/inference.py）：

1. logits = model(image)                      # 单模型
   logits = mean(model_i(image))              # 集成：对各成员的 log-softmax 取平均

2. TTA（若开启）：
   logits = (log_softmax(logits) + log_softmax(model(flip(image)))) / 2

3. 先验校正（τ ≠ 0 时）：
   logits ← logits − τ · log(π)               # π_c = 训练集第 c 类的样本占比

4. probs = softmax(logits)
   index = argmax(probs);  confidence = max(probs)

5. 拒识（t > 0 时）：
   if confidence < t:  index ← 50 (unknown)

6. 输出 label_id / label_name / confidence / is_unknown

3.1 先验校正 τ（prior / logit adjustment）

公式：

$$z'_c = z_c - \tau \cdot \log \pi_c, \qquad \pi_c = \frac{n_c}{N}$$

其中： - $z_c$ 是模型对第 c 类的 logit（这里实际用的是 log-softmax 后的值）； - $n_c$ 是第 c 类在训练集中的样本数； - $N$ 是训练集总样本数（7,494）； - $\tau$ 是校正强度。

本项目的先验（来自 configs/data_stats.json）：

π_unknown  = 1960 / 7494 = 0.2615
π_目标车型 ≈  110 / 7494 = 0.0147
log 先验差 = log(0.2615) − log(0.0147) ≈ 2.88

也就是说，unknown 的训练样本占比是单个目标车型的 17.8 倍。

τ 的直觉：

τ 效果
τ = 0 不做校正，保留模型学到的训练集先验（倾向预测 unknown）
τ > 0 把训练先验减掉，让模型更"平等"地对待每个类别 → 更少预测 unknown
τ = 1 完全按"类别等概率"决策，与 Macro-F1 的等权口径一致
τ < 0 反过来放大训练先验 → 更倾向预测 unknown

⚠️ 关键发现（本项目最重要的实验结论之一）：

对无类别权重训练的基线模型，τ 的最优点恰好落在 τ = 0： 无论往哪个方向校正，Macro-F1 都下降。

τ −0.5 −0.15 0 +0.15 +0.5 +1.0
Macro-F1 0.8290 0.8449 0.8475 0.8450 0.8411 0.8281

原因：unknown 有双重身份——

  • 它在训练集中占 26.2%（样本量是单个车型的 17.8 倍）；
  • 但它同时是 98 个来源车型的并集，类内异质性远高于任何单个目标车型。

样本量的优势恰好补偿了类内异质性带来的学习难度，两者在 Macro-F1 口径下正好抵消。 所以不能想当然地做类别平衡。

τ 的取值必须由验证集扫描决定，不能照搬：

模型 训练配方 最优 τ
A 基线 ResNet18@160，无类别权重 0.00
B 类别平衡 ResNet18@160，class_weight=inverse −0.40
C1 改进 ResNet18@224 强增强 +0.10
C2 骨干 ResNet50@224 强增强 −0.20
C3 集成 C1 + C2 +0.05

同一个数据集、同一个任务，最优 τ 从 −0.40 变到 +0.10 —— 完全取决于训练配方。 这就是为什么必须对每个模型单独跑 calibrate.py。

3.2 拒识阈值 t（unknown_threshold）

规则：

if max(softmax(logits)) < t:
    predicted_label ← "unknown"

本项目最终值：t = 0.25（集成模型）。

各模型的最优 t：A 0.40 / B 0.50 / C1 0.20 / C2 0.20 / C3 0.25。

收益很小（约 +0.003 ~ +0.005），原因是本任务的主要错误是高置信度错误：

日产_轩逸  →  unknown   conf = 0.991     ← 模型以 99% 的置信度认错
日产_轩逸  →  unknown   conf = 0.987
大众_朗逸  →  unknown   conf = 0.975
日产_轩逸  →  unknown   conf = 0.969

模型不是"不确定"，而是"非常确定地认错"。阈值只能拦"不自信"的样本，拦不住这种错误。

所以任务书 5.5 节说"低置信度处理不能替代 unknown 类别的训练"是完全正确的。 本项目把阈值定位为"给用户的一个友好提示开关"，而不是提升指标的手段。

3.3 为什么 τ 与 t 要联合扫描

两者作用在流程的不同位置（τ 改 logits，t 改最终决策），且都影响 unknown 的预测率， 所以它们不独立。本项目做的是 17 × 12 = 204 组网格扫描， 按验证集 Macro-F1 取全局最优。

找最优组合的命令：

python src/calibrate.py --run <run> --tta-hflip

输出 outputs/runs/<run>/calibration.json，其中 recommended 字段就是可直接使用的两个值。

4. 推理时的两条路径

4.1 单模型路径

from cardex.inference import CarClassifier
clf = CarClassifier(
    "outputs/checkpoints/improved_resnet50_224/best.pt",
    tta_hflip=True,
    prior_adjust_tau=-0.20,      # 来自该 run 的 calibration.json
    unknown_threshold=0.20,
)
r = clf.predict_path("图片.jpg", top_k=5)
print(r["label_id"], r["label_name"], r["confidence"], r["is_unknown"])

4.2 集成路径（本项目最终交付用的）

from cardex.inference import CarEnsemble
ens = CarEnsemble(
    ["outputs/checkpoints/improved_resnet18_224/best.pt",
     "outputs/checkpoints/improved_resnet50_224/best.pt"],
    tta_hflip=True,
    prior_adjust_tau=0.05,       # 来自 final_model_choice.json
    unknown_threshold=0.25,
)
r = ens.predict_path("图片.jpg", top_k=5)

集成的数学形式（几何平均）：

$$z^{\text{ens}}c = \frac{1}{M}\sum\left(\log p_m(c) - \tau \log \pi_c\right)$$}^{M

再对 $z^{\text{ens}}$ 做 softmax。

因为 $-\tau\log\pi_c$ 对所有成员相同，它等价于"先平均各成员的 log 概率，再做一次先验校正"。 集成与标定的顺序不能颠倒，finalize.py 与 CarEnsemble 都严格按上面的顺序实现。

5. 混淆矩阵怎么读

outputs/runs/<run>/eval_confusion_matrix.csv 是 51×51 的表：

  • 行 = 真实类别，列 = 预测类别（顺序 = 索引 0~50）；
  • M[i][j] = 真实第 i 类、被判成第 j 类的张数；
  • 对角线是正确预测，非对角线是错误。

三种典型症状：

症状 表现 含义
某行大量落在 unknown 列 M[i][50] 很大 该类被大量误拒（多世代问题、图像差异大）
unknown 行大量落在某些列 M[50][j] 较大 某些来源车型与目标车型太像
两个目标类互相混淆 M[i][j] 与 M[j][i] 都大 两类造型高度相似，选类时可考虑避开其一

本项目的实测（C1 的 top 混淆对）：

日产_轩逸      → unknown   7 次  (20.0% of 该类)      ← 症状 1
大众_朗逸      → unknown   7 次  (19.4% of 该类)      ← 症状 1
福特_福克斯    → unknown   6 次  (16.7% of 该类)      ← 症状 1
unknown        → MINI_MINI 5 次  (0.85% of unknown)   ← 症状 2
雷克萨斯_ES    → unknown   4 次  (10.8% of 该类)

结论：绝大多数严重混淆对都是"真实车型 → unknown"， 即"模型把见过的车型判成了不认识"，而不是"车型之间互相认错"。 这直接指向了数据层面的问题（见文档 07 第 5 节）。

6. 训练期选模型用什么指标

任务书 4.3 节要求：

训练期间，在包含 50 个目标车型和 unknown 的验证集上使用同一口径的 Macro-F1 选择模型和调整参数，不使用测试图片。

本项目的实现（src/cardex/engine.py）：

  • 每一轮结束后都在验证集上算一次 51 类 Macro-F1；
  • best.pt 保存的是 Macro-F1 最高的那一轮（不是最后一轮）；
  • 所有超参数决策（骨干、分辨率、增强、τ、t）全部基于 data/val；
  • 从未使用任何测试图片——教师提供的压缩包内本身也只有 train/ 与 val/。

summary.json 的 history[] 里每轮的 val_macro_f1 就是选模型依据。

本轮最优 vs 最终最优（C1）：

epoch 10 12 14 16 18
val Macro-F1 0.9243 0.9387 0.9433 0.9461 0.9482

所以 best.pt = epoch 18。

8. 一个容易混淆的点：confidence 到底是谁的概率

confidence = softmax 后的最大概率，且它是在应用了 τ 校正之后计算的。

所以： - τ > 0 时，unknown 的 logit 被压低，confidence 的分布会整体上移（模型更"自信"）； - τ < 0 时相反。

这意味着 confidence 不是一个绝对的"模型确信度"，它包含了人为的先验调整。 在报告里描述 confidence 时应该说明这一点。

另外，predictions.csv 里的 confidence 就是上面这个值（保留 6 位小数）， 教师如果要用它做置信度分析，需要知道它已经被 τ 校正过。

9. 局限性说明（写进报告的"不足"）

  1. τ 与 t 是在同一份验证集（2,422 张）上扫描 204 组选出的最优， 存在过拟合验证集的风险，可能高估约 0.003。 更严谨的做法是用交叉验证或单独划出一份校准集。
  2. "选哪个候选"（C1 / C2 / 集成）也是在同一个验证集上比较得出的，同理存在轻微乐观偏差。
  3. 拒识阈值收益极小，说明本任务的主要误差来源不是"不确定性"，而是"数据本身的类内多模态" （同一车型名下的多个世代），阈值类手段治标不治本。
  4. bf16 推理在不同批次组合下有极小的数值差异（实测 confidence 最大差 0.0037）， 不影响标签（200/200 一致），但会让"重算的 confidence"与"提交的 confidence"有微小出入。
