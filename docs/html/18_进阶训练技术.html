18 · 进阶训练技术　（19/26）

18 · 进阶训练技术详解

这篇讲三件事：对比学习、OOD 检测、容量与分辨率。 每一项都从"为什么需要它"讲起，给出公式、实现细节、以及本项目的实测结果 （包括失败的尝试 —— 它们往往比成功的更有信息量）。

前置阅读：13 · 技术栈全解（迁移学习/数据增强基础）、 15 · 微调实战指南（学习率与灾难性遗忘）。

第一部分：对比学习 —— 让近似款在特征空间拉开距离

1.1 问题的根源：交叉熵不关心"错得有多离谱"

我们的任务是细粒度分类：MINI 和 MINI CLUBMAN、A6 和 A6L，外观差异极小。

交叉熵损失只做一件事：

$$L_{CE} = -\log \frac{\exp(z_y)}{\sum_c \exp(z_c)}$$

它要求"正确类别的 logit 最大" —— 仅此而已。它不知道也不关心： 被压下去的那些类别，在特征空间里离正确答案有多近。

后果是：模型可以学会"给 MINI 打 0.51、给 CLUBMAN 打 0.49"就交差。 这在测试集上表现为边缘样本频繁翻车，而且任何阈值调参都救不了 —— 因为特征本身就没有分开。

1.2 度量学习的基本思想

要解决这个问题，需要在特征空间上直接施加约束：

同类样本的距离要小，异类样本的距离要大。

这就是度量学习（metric learning）。经典方法有三元组损失（Triplet Loss）、 N-pair Loss、Proxy Anchor 等，但它们都有一个共同的麻烦： 要精心构造"难负样本"，采样策略对结果影响巨大。

1.3 SupCon：把"正负样本对"做成一个损失

Supervised Contrastive Learning（Khosla et al., NeurIPS 2020）给出了一个更优雅的形式。

第一步：定义相似度。 把特征 $z$ 做 L2 归一化后，点积就是余弦相似度：

$$\text{sim}(z_i, z_j) = \frac{z_i^\top z_j}{|z_i|\,|z_j|}$$

第二步：定义损失。 对一个锚点 $i$，把它所有同类样本 $p \in P(i)$ 当作正样本：

$$L_{sup} = \sum_{i \in I} \frac{-1}{|P(i)|} \sum_{p \in P(i)} \log \frac{\exp(z_i \cdot z_p / \tau)}{\sum_{a \neq i} \exp(z_i \cdot z_a / \tau)}$$

这个公式在做什么：对每个正样本对，要求"这个正样本的相似度"相对于 "所有其他样本的相似度之和"要尽可能大。

关键洞察：分母是对所有负样本求和。在梯度里，相似度越高的负样本， 被惩罚得越狠 —— 也就是说，"很像但不是同类"的样本会贡献最大的梯度。

这正是我们要的：MINI CLUBMAN 会被自动识别为"最难的负样本"，被用力推开。 不需要手工构造三元组。

温度系数 τ 的作用

$\tau$ 控制"关注多少难度的负样本"：

τ 效果
大（0.5） 所有负样本权重接近，损失平滑
小（0.05~0.1） 只关注最像的那几个负样本，梯度集中

细粒度识别通常用 0.05~0.1，本项目取 0.1。

注意：除以 $\tau$ 在实现上会放大相似度数值 10 倍， 这让 exp 极易溢出。所以实现里必须做数值稳定处理（见 1.6）。

1.4 ⚠️ 本项目最关键的设计决策：用 fine 标签，不用 51 类标签

这是一个如果不注意就会把模型训坏的陷阱。

我们的数据集里，unknown 是一个"类"，但它其实是 98 个不同车系的混合体 （34 个同品牌近似款 + 64 个其他品牌）。

如果对 51 个标签做 SupCon 会怎样？

损失函数会认为"所有 unknown 样本都是同类"，于是把它们在特征空间里拉成一团。 这意味着让 MINI CLUBMAN 和一辆卡车变得相似 —— 这不仅无益，而且直接损害模型区分"真 unknown"与"真已知类"的能力。

正确做法：用 fine 标签做对比损失。

fine 标签空间 = 50 个已知车型 + 98 个 unknown 来源车系 + 1 个"其他" = 149 类

来源标签不需要额外标注 —— 它就藏在文件名里：

data/train/unknown/0702_0237.jpg
                    ^^^^
                    源类别 ID = 0702 = MINI_MINI CLUBMAN

于是对比损失变成：

  • 同源的 unknown 样本 → 拉近（它们确实是一类车）
  • 异源的 unknown 样本 → 推远
  • MINI CLUBMAN（unknown）↔ MINI（已知类）→ 推远 ← 这一条就是我们真正想要的
  • 同时，分类头仍然只预测 51 类（unknown 仍然是"一类"）

一句话总结：分类头负责"是不是我们要的车"， 对比损失负责"在特征空间里把每款车摆到正确的位置"。 两者用不同的标签空间，各司其职。

1.5 ⚠️ 第二个坑：batch 里凑不出正样本对

SupCon 的分母需要对负样本求和，分子需要正样本。 但我们的现实是：

51 个类别，batch = 32  →  平均每个类别在一个 batch 里只有 0.6 张图

绝大多数样本在 batch 里根本没有同类样本 → 没有正样本 → 该样本对损失贡献 0。

解决方案：双视图（two-view）。

对同一张 PIL 图独立地跑两遍随机增强，得到两个不同视角：

# src/cardex/data.py —— CarDataset(n_views=2)
image = torch.stack([self.transform(image) for _ in range(2)])   # (2, C, H, W)

这两个视角天然互为正样本（它们本来就是同一张图）。再配合 fine 标签， 每个样本至少有一个正样本，且常常还有同类的其他样本。

代价：每个 epoch 的前向次数翻倍（batch × views），训练时间约 ×2。

实现细节：把 (B, V, C, H, W) 展平成 (B×V, C, H, W) 一次前向算完， 比循环调用快得多；fine 标签用 repeat_interleave(V) 同步扩展。

images = images.view(B * V, *images.shape[2:])
fine = fine.repeat_interleave(V)

1.6 第三个坑：投影头（projection head）

为什么不直接在 2048 维特征上算对比损失？

SimCLR 论文发现：对比损失会消耗表示能力。如果直接在特征上施加对比约束， 模型会为了满足对比目标而丢掉对分类有用的信息 —— 这叫表示崩塌（representation collapse）。

解法：在特征后面接一个投影头（2 层 MLP），对比损失作用在投影空间：

骨干 → 2048 维特征 ─┬─→ 分类头 → 51 类 logits      （CE 损失作用于这里）
                    └─→ 投影头 → 128 维 → SupCon   （对比损失作用于这里）

对比约束被"缓冲"在投影空间里，分类用的还是原始 2048 维特征。 推理时投影头直接丢掉，零额外成本。

def build_proj_head(in_dim, hidden, out_dim):
    return nn.Sequential(
        nn.Linear(in_dim, hidden), nn.ReLU(inplace=True), nn.Linear(hidden, out_dim))

投影头的参数必须加到优化器里，否则它根本不更新、对比损失毫无作用。 而且要给更高的学习率（×5）：它和分类头一样是随机初始化的新模块， 而骨干是预训练的 —— 两者"成熟度"差得远。

1.7 ⚠️ 第四个坑：MixUp/CutMix 与 SupCon 互斥

MixUp 把两张图按比例混合，标签变成软标签（两类概率的线性组合）。

而 SupCon 需要硬标签来判断"谁是正样本"。软标签下没有明确的"同类"概念。

所以两者不能同时开，本项目在启用 SupCon 时自动关闭 MixUp/CutMix 并打警告。

这不完全是损失 —— MixUp 的作用是正则化、防过拟合， 而 SupCon 本身也是强正则化手段，两者功能有重叠。

1.8 实现细节：数值稳定性三件事

① L2 归一化

z = F.normalize(features, dim=1)     # 单位球面上，点积 = 余弦相似度

不做归一化的话，特征模长会主导相似度，温度系数失去意义。

② logsumexp 的稳定写法

$\exp(\text{sim}/\tau)$ 在 $\tau=0.1$、相似度 ~0.5 时是 $\exp(5) \approx 148$， 看着还好；但异常大的相似度（比如两个视角的同一张图，相似度 ~1.0） 是 $\exp(10) \approx 22026$，在 fp16 下会直接溢出成 inf。

所以必须先减去每行最大值：

sim = sim - sim.max(dim=1, keepdim=True).values.detach()   # 不影响 softmax 结果

.detach() 很重要 —— 最大值的梯度不应该回传（它只是个数值稳定技巧）。

③ 无正样本的样本要剔除

如果某个样本在 batch 里既没有同类、也没有第二个视图，$|P(i)| = 0$， $-\frac{1}{0}$ 会直接出 NaN，污染整个 batch 的梯度。

n_pos = pos.sum(dim=1)
valid = n_pos > 0                       # 没有正样本的样本跳过
if not bool(valid.any()):
    return features.new_zeros(())
loss = -(pos * log_prob).sum(dim=1)[valid] / n_pos[valid]

实测边界情况：4 个样本各不同类时，损失返回 0.0000（而不是 NaN）✅

④ fp16 → fp32 转换

投影输出必须 .float() 再算损失：

proj = proj_head(feats)
sc = supcon_loss(proj.float(), fine, temperature=supcon_temp)

因为在 autocast 下 proj 是 fp16，而损失里有 exp 和除法，精度不够会直接数值爆炸。

1.9 实测结果

训练配置（configs/train_r50_supcon.json）：

{
  "arch": "resnet50", "image_size": 288, "epochs": 16, "batch_size": 24,
  "supcon": true,
  "supcon_weight": 0.5,          // 总损失 = CE + 0.5 × SupCon
  "supcon_temperature": 0.1,
  "supcon_views": 2,             // 双视图
  "supcon_dim": 128,             // 投影维度
  "supcon_head_lr_mult": 5.0,    // 投影头是随机初始化的，给更高学习率
  "mix_prob": 0.0                // 与 SupCon 互斥，自动关闭
}

总耗时 39.9 分钟（16 轮 / GPU）。比同分辨率基线慢 30%（双视图让前向翻倍）。

结果一：逐轮对比显示 SupCon 收敛更快

epoch 基线 r50_288 SupCon 差
9 0.9532 0.9621 +0.0089
10 0.9596 0.9663 +0.0067
11 0.9649 0.9689 +0.0040
13 0.9721 0.9722 +0.0001
最终 0.9739（20 轮） 0.9745（16 轮） +0.0006

SupCon 全程领先，而且用更少的轮数就达到了更高的精度 —— 因为它提供了额外的监督信号（特征空间的几何约束），信息量比单纯的交叉熵更大。 但随着基线多跑 4 轮，差距从 0.0089 收窄到 0.0006。

结果二：⭐ 特征空间确实被"拉开"了（核心机制验证）

这一项比 Macro-F1 更重要 —— 它直接验证了我们声称的机制，而不是靠指标间接推断。

在验证集（每类 20 张，共 1020 张）上度量特征空间的几何：

模型 类内距离 ↓ 类间距离均值 ↑ 类间最小距离 ↑ 可分性比值 ↑
基线 r50_288_from_scratch 0.0523 0.2592 0.1481 4.9556
SupCon 0.0469 0.2991 0.1583 6.3816
变化 −10% +15% +7% +29%
  • 类内距离 = 同类样本两两的平均余弦距离（越小越紧凑）
  • 类间距离 = 类中心之间的平均余弦距离（越大越可分）
  • 可分性比值 = 类间 / 类内 —— 综合评价特征空间的"拉开程度"

可分性从 4.96 提升到 6.38（+29%）。

最关键的一行是"类间最小距离" —— 它对应最像的那一对类中心。 从 0.1481 到 0.1583（+7%），说明最难区分的那一对确实被推开了。

结果三：hard_negative 到目标类的距离增加 21%

针对 34 个刻意设计的近似款（如 MINI CLUBMAN → 目标是 MINI）， 度量它们到目标类中心的余弦距离：

模型 hard_negative 到目标类中心距离 ↑
基线 0.2271
SupCon 0.2756（+21%）

这正是 SupCon 设计时瞄准的目标：让"看起来像但其实是另一款车"的样本远离目标类。

⚠️ 样本量说明：验证集里被标记为 hard_negative 的 unknown 样本只占少数， 在每类 20 张的子集上只有 7 个 —— 单独看"误拒率 0/7 vs 1/7"是噪声，不能下结论。 所以这里报告的是距离的均值（连续量，7 个样本也能看出趋势）， 而不是二值的"拒没拒对"。几何证据是可靠的，分类率证据需要全量验证集才有意义。

结果四：作为集成成员贡献了 +0.0010

配置 标定后 Macro-F1
r50_288_from_scratch 单独 0.9779
r50_288_supcon 单独 0.9781（+0.0002）
r50_352 单独 0.9806
r50_288_from_scratch + r50_352（原冠军） 0.9815
r50_288_supcon + r50_352 0.9825（+0.0010）

supcon + from_scratch（两个 288） 0.9810

有意思的现象：SupCon 单独只比基线高 0.0002，但作为集成成员贡献了 0.0010。

解释：SupCon 改变了特征空间的结构（可分性 +29%）， 所以它的错误模式和基线不一样 —— 这正是一个好的集成成员需要的。 它和 r50_352 的组合（0.9825）明显好于基线和 r50_352 的组合（0.9815）。

三人集成（0.9818）反而不如两人 —— 因为两个 288 模型彼此太像，稀释了 r50_352 的权重。

结果五：一个"没那么好"的信号

r50_288_supcon + r50_288_from_scratch（两个 288 模型集成）只有 0.9810， 低于任意一个与 352 的组合。这说明 SupCon 带来的多样性仍然受限于同一分辨率 —— 分辨率差异带来的多样性 > 损失函数差异带来的多样性。

结论：SupCon 是一个有效但增益有限的方法（净 +0.0010）。 它的价值主要体现在：① 收敛更快（少 20% 轮数）；② 特征空间更可分（+29%）， 这对后续可能的检索/聚类任务更有价值；③ 作为集成成员的多样性来源。 它没有像期望的那样一次性带来 +0.005~0.01 —— 因为剩余误差里 很大一部分是任务设计固有的难度（近似款本身就像），不是特征空间没分开。

第二部分：OOD 检测 —— 让模型知道自己不知道

2.1 分类准 ≠ 会拒识

我们的任务有两件事：

  1. 分类：把图片分到 51 类之一；
  2. 拒识：判断"这张图根本不属于这 51 类"。

第 2 件事在学术上叫 OOD 检测（Out-of-Distribution Detection）。 它和分类是两个不同的问题 —— 一个模型可以分类很准，但完全不会拒识。

为什么：softmax 是归一化的。即使模型对每一类都没信心（所有 logit 都很小）， 归一化之后仍然会出现一个"相对最高"的概率。于是 OOD 样本被误判为已知类。

2.2 三种 OOD 打分

[1] Max-Softmax（基线）

$$S_{MS}(x) = \max_c \frac{\exp(z_c)}{\sum_j \exp(z_j)}$$

低于阈值就拒识。最简单，但因为归一化丢掉了 logits 的绝对量纲。

[2] Energy-based（Liu et al., NeurIPS 2020）

$$E(x) = -T \cdot \log \sum_c \exp(z_c / T)$$

关键区别：它完全不做归一化。

直觉是： * 模型见过的东西 → logits 绝对值大 → $\log\sum\exp$ 大 → 能量低 * 模型没见过的东西 → logits 都接近 0 → $\log\sum\exp$ 小 → 能量高

所以能量高 → 判为 OOD。

温度 $T$ 的作用：$T$ 越大，$\log\sum\exp$ 越接近"logits 的最大值"（soft-max 极限）； $T$ 越小越接近"平均"。$T$ 需要扫。

[3] Mahalanobis（特征空间方法）

利用倒数第二层的特征空间几何：

  1. 在训练集特征上，为每个类 $c$ 拟合一个高斯分布：均值 $\mu_c$、共享协方差 $\Sigma$
  2. 对测试样本，算它到最近类中心的马氏距离：

$$S_{M}(x) = \min_c (f(x) - \mu_c)^\top \Sigma^{-1} (f(x) - \mu_c)$$

为什么用马氏距离而不是欧氏距离：协方差矩阵相当于"按各方向的数据方差做归一化" —— 方差大的方向惩罚小，方差小的方向惩罚大。这比欧氏距离合理得多。

实现要点： * 共享协方差用残差估计：$\Sigma = \frac{1}{N-C}\sum_i (f_i - \mu_{y_i})(f_i - \mu_{y_i})^\top$ * 必须加抖动保证可逆：cov += eye * 1e-3 * trace(cov)/d * 展开计算避免显式循环：$(x-\mu)^\top P (x-\mu) = x^\top P x - 2\mu^\top P x + \mu^\top P \mu$

2.3 ⚠️ 用哪个指标评价？AUROC 还是最终 Macro-F1

这是本篇最重要的一节。

  • AUROC：衡量"这个分数本身有多好地把 known 和 unknown 分开"，与阈值无关；
  • Macro-F1：分类 + 拒识合起来的最终效果，依赖阈值。

很多人只报 AUROC 就宣称方法更好 —— 这是不够的。 AUC 高只说明分数排序好，但阈值是在真实数据上标定的， 它的位置决定了实际效果。一个 AUC 高但阈值和分类边界对不齐的分数，实际用起来反而更差。

2.4 本项目的实测结果（负结果）

在最终冠军模型（r50_288 + r50_352，多裁剪 TTA）上：

方法 Macro-F1 AUROC 阈值
Max-Softmax（原方法） 0.9815 ★ 0.8441 0.1597
Energy T=0.5 0.9810 0.8564 −3.548
Energy T=1.0 0.9805 0.8594 −4.732
Energy T=2.0 0.9805 0.8651 −8.391
Energy T=5.0 0.9805 0.8260 −20.077
Mahalanobis 0.9805 0.7787 69880.5
Energy + Mahalanobis 融合 0.9806 0.8735 ★ +4.546

读出来的三件事：

① Energy / 融合方案在纯 OOD 检测上确实更强。 AUROC 从 0.8441 提升到 0.8735（+0.029） —— 约 3 个点，是真实的改进。 Energy 的温度 $T$ 越大 AUROC 越好（T=2 时 0.8651），验证了"不做归一化"的价值。

② 但 AUROC 的提升没有转化为 Macro-F1。 Macro-F1 上，Max-Softmax 仍然最好（0.9815），所有替代方案都略低（0.9805~0.9810）。

③ 原因分析： Macro-F1 是联合指标。max-softmax 虽然 OOD 判别力弱， 但它和分类置信度天然对齐 —— 一个低置信度的样本，既可能是分类困难，也可能是 OOD， 两者本来就该一起处理。而 Energy/Mahalanobis 是独立的分数， 它的阈值和分类决策边界对不齐：调高会让已知类被误拒，调低会让 unknown 漏网。

结论：我们保留 max-softmax。 但 AUROC 的改进说明： 如果未来场景更看重"不要瞎认"（比如安全关键应用），Energy/融合方案更值得考虑。

这个负结果本身很有价值：它说明"用学术上更强的方法"不一定在你的指标上更好。 选方法要看最终指标，不能只看论文里的 AUROC。

第三部分：容量与分辨率 —— 什么是真正的瓶颈

3.1 分辨率的物理意义

为什么提高分辨率对细粒度识别特别有效？

车型之间的差异往往在局部细节上：

对比 关键差异 在 224×224 下
奥迪 A6 vs A6L 后门长度 差约 4 像素
大众 朗逸 vs 宝来 格栅条纹 一个条纹约 1~2 像素
MINI vs MINI CLUBMAN 车身长度、对开门 差约 10 像素

224→288 让像素量增加 65%，224→352 增加 147%。 原本 1 像素的差异变成 2.5 像素 —— 对卷积核来说，这是"能不能分辨"的差别。

实测印证（本项目，同一骨干 ResNet50，统一用多裁剪 TTA + 验证集标定）：

训练分辨率 标定后 Macro-F1 相对上一档 训练耗时
224 0.9592 ※ — 11.8 min（GPU）
288 0.9779 +0.0187 30.7 min
352 0.9806 +0.0027 40.9 min
416 0.9815 +0.0009 49.6 min

※ 224 那一行是早期用 hflip TTA 测的（当时还没实现多裁剪），所以它偏低、真实差距比表上更大。 288 及以后都是多裁剪口径，可直接比较。

读出来的规律：

  • 224 → 288 一步就 +0.019，比换更大的骨干（ResNet18→ResNet50 只有 +0.008）收益大一倍多；
  • 但收益快速递减：288→352 只有 +0.0027，352→416 只剩 +0.0009；
  • 而训练耗时线性增长：416 比 288 慢 62%。

这是一条典型的饱和曲线：分辨率提升到某个点之后， "图上信息量不足"不再是瓶颈，瓶颈转移到了别处（数据量、类别本身的相似度）。

实用建议：本任务上 288~352 是性价比拐点。 416 虽然绝对分数最高，但多花 62% 的训练时间只换来 +0.0009 —— 除非追求极致，否则不值得。它更适合作为集成成员（提供不同尺度的视角）。

3.4 骨干容量的边际收益

骨干 参数量 输入 标定后 Macro-F1
ResNet18 11.2 M 224 0.9510
ResNet50 23.6 M 224 0.9592
Wide ResNet50_2 66.9 M 288 （本项目实测中）

参数量增加 2.1 倍（ResNet18→ResNet50），精度只提升 0.008； 而分辨率从 224 提到 288（参数量不变）提升了 0.019。

结论：瓶颈在"输入信息量"，不在"模型容量"。 这符合直觉 —— 如果图上本来就没有足够的信息，再大的模型也学不出区分能力。 所以调参顺序应该是：先把分辨率拉满，再考虑换大模型。

3.2 ⚠️ 训练与推理的分辨率必须一致

一个常见的错误：模型在 224 上训练，推理时喂 288 的图"想让它看得更清"。

实测是掉点的：

模型（224 训练） @224 @288 @352
improved_resnet50_224 0.9597 0.9509 ↓ 0.9236 ↓
improved_resnet18_224 0.9507 0.9354 ↓ 0.8926 ↓

原因：模型只在 224 的尺度上见过物体。给它 288 的图， 物体的表观尺寸变了，卷积核的感受野对应的物理尺寸也变了， 特征分布整体偏移 —— 这叫训练/测试分辨率不匹配。

正确做法：在目标分辨率上训练（哪怕从 ImageNet 权重重新开始也比"缩放推理"强）。

3.3 多尺度 TTA vs 多裁剪 TTA（名字像，效果相反）

做什么 结果
多尺度 TTA 把图缩放到训练时没见过的尺寸 ❌ 只 +0.0005
多裁剪 TTA 保持训练分辨率，只换裁剪位置（中心+四角） ✅ +0.0025

多裁剪为什么有效：区分车型的关键部位（格栅、大灯）不一定落在画面正中央。 五个裁剪位置相当于让模型"多看几眼"，而且每个位置的尺度都是它熟悉的。

代价：推理时间约 ×5（10 个视角 vs 2 个）。

3.4 骨干容量的边际收益

骨干 参数量 输入 标定后 Macro-F1 训练耗时
ResNet18 11.2 M 224 0.9510 8.7 min
ResNet50 23.6 M 224 0.9592 11.8 min
ResNet50 23.6 M 288 0.9779 30.7 min
Wide ResNet50_2 66.9 M 288 0.9798 36.9 min
ResNet50 23.6 M 416 0.9815 49.6 min

三组对比说明了一切：

对比 参数变化 精度变化
ResNet18 → ResNet50（同 224） ×2.1 +0.0082
ResNet50 → Wide ResNet50_2（同 288） ×2.8 +0.0019
ResNet50：288 → 416（参数不变） ×1.0 +0.0036

结论：瓶颈在"输入信息量"，不在"模型容量"。

  • 参数量翻 2~3 倍，只换来 0.002~0.008；
  • 分辨率提一档（参数完全不变），换来 0.004，而且只需要改一个数字。

所以调参顺序应该是：先把分辨率拉满，再考虑换大模型。 换大模型还要付额外的代价：Wide ResNet50_2 的权重是 267 MB（ResNet50 的 2.7 倍）， 推理也更慢 —— 在一人集成里它是划算的，但如果只是"想更强"，先调分辨率。

第五部分：本轮三项尝试的总结

5.1 结果总表

尝试 单项效果 对最终集成的贡献 评价
对比学习 SupCon 单独 +0.0002 +0.0010 ✅ 有效，机制已验证
更高分辨率 416 单独 +0.0036（对 288） +0.0016 ✅ 性价比最高
更大骨干 Wide R50_2 单独 +0.0019（对 288） +0.0016 ✅ 有效但代价大
Energy-based OOD AUROC +0.029 −0.001 ❌ 负结果

最终配置：r50_416 + r50_288_supcon + wide_r50_2_288，Macro-F1 = 0.9845 （本轮 0.9815 → 0.9845，+0.0030）

5.2 三个反直觉的发现

① 模型自己学会了拒识，不需要事后阈值

冠军配置的拒识阈值是 0.00 —— 意味着完全不做事后拒识。但它的表现反而更好：

threshold = 0.00
  unknown 检出率 = 0.9575    （95.75% 的 unknown 被正确识别）
  已知类误拒率   = 0.0120    （只有 1.2% 的已知类被误拒）
  unknown 的 F1   = 0.960     （早期 0.915 → r50_288 时 0.941 → 现在 0.960）

这说明：当模型足够强时，"拒识"这件事被真正学进了网络内部（unknown 作为第 51 类， 模型自己就会输出它），而不是靠外挂一个阈值来兜底。 这比"靠阈值拒识"更可靠 —— 阈值是事后补丁，学到的能力才是真本事。

② OOD 分数更强 ≠ 最终指标更好

Energy/Mahalanobis 的 AUROC 明显更高（0.844 → 0.874），但 Macro-F1 反而更低。 因为 AUROC 只衡量排序质量，而 Macro-F1 还依赖阈值的落点 —— max-softmax 和分类置信度天然对齐，替代方案的阈值和分类决策边界对不齐。

③ 更大骨干的收益远不如提高分辨率

参数量 ×2.8 只换来 +0.0019；而分辨率 288→416（参数不变）换来 +0.0036。 "看不清"永远比"不够聪明"更致命。

5.3 一个诚实的方法论提醒

本轮四项尝试里，只有三项有效，而且增益都远小于最初的乐观估计：

尝试 预期（我一开始的估计） 实际
对比学习 +0.005 ~ 0.01 +0.0010
更大骨干/更高分辨率 +0.002 ~ 0.004 +0.0016 ~ 0.0036
OOD 改进 "unknown F1 提升" −0.001

原因：这些方法的"理论增益"是在误差主要来自某个可修复的缺陷时才能兑现的。 而我们的模型已经到 0.9815，剩余误差里很大一部分是任务设计的固有难度 （刻意构造的近似款 hard_negative），不是方法能解决的。

这本身就是一条重要的经验：分数越高，每种方法的边际收益越小。 在 0.85 → 0.95 阶段，方法选对能一次涨 0.05；在 0.98 阶段，所有方法加起来只涨 0.003。 判断"还能不能涨"的正确方式不是看有什么方法可用，而是看剩下的错误是什么性质。

4.1 先诊断，再选方法

不要一上来就试"先进方法"。 先做误差结构分析：

本项目：61 张错误 / 2422
  unknown 被误认  25 张   ← 其中大部分是刻意设计的 hard_negative（近似款）
  已知类被判 unknown 46 张
  → unknown 完全修好只能 +0.0012 → 不是主要矛盾
  → 主要矛盾在"近似款分不开" → 对比学习才是对症的

4.2 优先试"免费"和"便宜"的

按成本排序，逐级尝试：

层级 手段 成本
1 阈值/后处理标定 零
2 TTA（多裁剪） 零训练，推理 ×5
3 集成已有模型 零训练，推理 ×N
4 超参/分辨率重训 几十分钟 GPU
5 损失函数改造（SupCon） 改代码 + 几十分钟
6 新架构 大量调试

本项目在层级 1、2 上的投入产出比最高（多裁剪 +0.0025，完全免费）。

4.3 警惕"看起来该有用"的方法

本项目试过、并且失败的方法：

方法 结果 失败原因
多尺度 TTA − 训练/测试分辨率不匹配
快照集成 −0.0017 同一次训练的快照相关性太高
调低拒识阈值 −0.0011 当前值已最优
弱模型加入集成 −0.003~−0.01 等权平均里弱成员是负资产
Energy OOD AUROC +0.03 但 F1 − 阈值与分类边界对不齐

共同教训：这些方法在别的问题上都被证明有效，但在这个问题上无效。 判断依据只能是自己的实测指标，不能是论文里的数字。

4.4 关键指标要能复现

本项目踩过的两个"不报错的 bug"：

  1. 缓存不看权重 → 重训后静默复用旧结果，指标一字不差却没更新；
  2. 标定口径 ≠ 生产口径 → 实验 0.9815，生产只有 0.9695，差 0.012。

共同特征：不崩、不报错，只是"结果莫名不对"。

对策：写一个 reproduce_production.py，用生产代码跑一遍验证集， 和实验脚本的数字对比。差异 > 0.003 就说明两个实现不一致。
