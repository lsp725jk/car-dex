# 04 数据格式与文件约定

本文档给出项目中**所有数据文件的精确格式**：字段名、类型、取值范围、示例、谁生产、谁消费。
目的是让任何人（包括未来的自己、队友、教师）都能不读代码就读懂数据。

---

## 0. 文件关系图

```
教师提供                          本项目生成
─────────                        ──────────
class_info.json ──┐
                  ├─► select_classes.py ─► classes.txt ★
selection.json ───┘                     ├─► class_map.json
                                        ├─► unknown_sources.json
                                        └─► selection_report.txt

classes.txt ──────┐
unknown_sources.json ─┴─► prepare_data.py ─► data/train|val/<类别>/…
                                          ├─► data_stats.json
                                          └─► data_manifest.csv

data/ + train_*.json ─► train.py ─► checkpoints/<run>/best.pt
                                 ├─► runs/<run>/train.log
                                 ├─► runs/<run>/summary.json
                                 └─► runs/<run>/val_report.json

best.pt ─► calibrate.py ─► runs/<run>/calibration.json
best.pt ─► evaluate.py  ─► runs/<run>/eval_report.json + 混淆矩阵/错误样本

                            ├─► predictions.meta.json
                            └─► reports/final_model_choice.json
```

标 ★ 的是任务书要求的提交物。

## 1. `classes.txt` ★

| 项目 | 规定 |
| --- | --- |
| 文件名 | 固定为 `classes.txt`，放在**项目根目录** |
| 编码 | UTF-8，**不带 BOM** |
| 行数 | **恰好 50 行**（每行一个类别 ID，最后有一个换行符） |
| ID 格式 | 恰好 4 位数字，**保留前导零**，如 `0000`、`0987` |
| 唯一性 | 50 个 ID 不得重复 |
| 顺序 | 按类别 ID **升序** |
| 取值范围 | 必须属于教师提供的 **827 类** |
| unknown | **不写入本文件**。unknown 是模型的第 51 类 |
| 大小 | 250 字节 |

实际内容（前 10 行）：

```
0003
0019
0025
0035
0061
0119
0161
0183
0194
0222
```

**唯一生产者**：`src/select_classes.py`
**消费者**：`src/prepare_data.py`、`src/predict_batch.py`（校验标签合法性）、
`src/verify_submission.py`、教师侧

**自检**：

```bash
python -c "raw=open('classes.txt','rb').read(); s=raw.decode('utf-8'); ids=s.split(); \
print('行数',len(ids),'| 四位数字',all(len(x)==4 and x.isdigit() for x in ids), \
'| 升序',ids==sorted(ids),'| 无BOM',not raw.startswith(b'\xef\xbb\xbf'))"
```

## 2. `predictions.csv` ★

| 项目 | 规定 |
| --- | --- |
| 编码 | UTF-8，无 BOM |
| 表头 | **固定为** `image_id,predicted_label,confidence`（顺序、拼写都不能变） |
| `image_id` | 包含扩展名的图片文件名，例如 `0003_0009.jpg`；**每张图片恰好一条记录**，不得重复、不得遗漏、不得添加教师指定之外的图片 |
| `predicted_label` | `classes.txt` 中的四位车型 ID（保留前导零）**或**小写 `unknown` |
| `confidence` | 0~1 的有效数值（本项目保留 6 位小数） |

实际内容：

```csv
image_id,predicted_label,confidence
0003_0009.jpg,0003,0.962251
0003_0016.jpg,0003,0.933231
0003_0017.jpg,0003,0.956696
...
0984_0471.jpg,unknown,0.823122
```

**当前状态**：2,422 条记录，预测为 unknown 的有 609 条（25.1%），
confidence 分布 min 0.11 / mean 0.81 / max 0.999。

**生产者**：`src/predict_batch.py`（单模型）或 `src/finalize.py`（集成，本项目用的这条）
**消费者**：教师（用于计算最终测试 Macro-F1）、`src/score_predictions.py`、`src/verify_submission.py`

**⚠️ 最重要的约束**：`image_id` 必须与教师指定的测试图片**逐张对应**。
多一条、少一条、重名都会被判为不合格。

**自检**：

```bash
python src/verify_submission.py    # 第 [5] 组检查会逐项验证
```

## 3. `configs/class_map.json` — 标签映射（最关键）

```json
{
  "note": "索引 0~49 按 classes.txt 行顺序对应 50 个目标车型；索引 50 对应 unknown。训练/保存/Web 推理/批量推理共用本映射。",
  "index_to_id":    { "0": "0003", "1": "0019", ..., "49": "0987" },
  "index_to_name":  { "0": "宇通客车_宇通T7", "1": "吉利汽车_星瑞", ..., "49": "领克_领克03" },
  "index_to_group": { "0": "轻客", "1": "轿车", ..., "49": "轿车" },
  "id_to_index":    { "0003": 0, "0019": 1, ..., "0987": 49 },
  "unknown_index": 50,
  "unknown_label": "unknown",
  "num_classes": 51
}
```

| 字段 | 类型 | 键 | 值 | 示例 |
| --- | --- | --- | --- | --- |
| `index_to_id` | object | 字符串形式的索引 `"0"`~`"49"` | 四位车型 ID | `"0" → "0003"` |
| `index_to_name` | object | 索引字符串 | 车型中文名（取自 `name_from_new`） | `"0" → "宇通客车_宇通T7"` |
| `index_to_group` | object | 索引字符串 | 车身大类 | `"0" → "轻客"` |
| `id_to_index` | object | 四位车型 ID | 整数索引 | `"0003" → 0` |
| `unknown_index` | int | — | 固定 `50` | |
| `unknown_label` | str | — | 固定 `"unknown"`（小写） | |
| `num_classes` | int | — | 固定 `51` | |

**三条不可违背的约定**：

1. **索引 0~49 的顺序 = `classes.txt` 的行顺序**。
   `verify_submission.py` 会逐项比对，不一致直接报 FAIL。
2. **索引 50 永远是 unknown**，无论 `classes.txt` 怎么变。
3. **这份映射随 checkpoint 一起保存**（`ckpt["class_map"]`），
   所以加载旧模型不会因为 `classes.txt` 改动而错位。

**生产者**：`src/select_classes.py`
**消费者**：`src/cardex/paths.py::load_class_map()` → 被 `data.py` / `inference.py` / 所有脚本间接使用

## 4. `configs/class_info.json` — 教师提供的类别说明

827 条记录的数组：

```json
[
  {
    "id": "0000",
    "name_from_new": "江铃_凯运",
    "name_from_old": "江铃_凯运==JMC_Kaiyun",
    "type_info": "卡车####轻卡==Truck####Light Truck"
  },
  {
    "id": "0001",
    "name_from_new": "远程汽车_远程星享H",
    "name_from_old": "远程汽车_远程星享H==Farizon Auto_Farizon Star H",
    "type_info": "卡车####轻卡==Truck####Light Truck"
  }
]
```

| 字段 | 格式 | 说明 |
| --- | --- | --- |
| `id` | 四位数字字符串 | **类别 ID 的唯一权威来源**（`classes.txt` / `predictions.csv` 用它） |
| `name_from_new` | `品牌_车型` | **标签名的唯一权威来源**（展示、查询、报告中一律用它） |
| `name_from_old` | `中文==English` | 旧版命名，仅作参考 |
| `type_info` | `中文大类####中文细分==英文大类####英文细分` | 类型信息 |

**`type_info` 的解析方式**（`src/inventory.py`）：

- 中文大类 = `type_info.split("==")[0].split("####")[0]` → 如 `卡车`
- 车身类型 = `type_info.split("==")[-1].split("####")[-1]` → 如 `Light Truck`

827 类的中文大类分布：SUV 372 / 轿车 259 / 卡车 70 / MPV 46 / 跑车 37 / 微面 22 / 轻客 21。

## 6. `configs/unknown_sources.json` — unknown 来源清单

```json
{
  "note": "unknown 样本来源。train/unknown 取这些类别的训练图片，val/unknown 取这些类别的验证图片，训练与验证样本不重复，且完全不使用测试图片。",
  "train_per_source": 20,
  "val_per_source": 6,
  "seed": 20250914,
  "hard_negative_count": 34,
  "other_brand_count": 64,
  "source_count": 98,
  "sources": [
    {
      "id": "0976",
      "name": "星途_星途凌云",
      "brand": "星途",
      "category": "SUV",
      "body_type": "Mid-size SUV",
      "train": 116,
      "val": 37,
      "source_kind": "hard_negative",
      "target_class_id": "0418"
    },
    {
      "id": "0847",
      "name": "大众_蔚揽",
      "brand": "大众",
      "category": "轿车",
      "body_type": "Mid-size Sedan",
      "train": 105,
      "val": 35,
      "source_kind": "other_brand",
      "target_class_id": ""
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `train_per_source` / `val_per_source` | 每来源类别的采样上限 |
| `seed` | 抽样随机种子（固定，保证可复现） |
| `hard_negative_count` | 同品牌兄弟车型类数（34） |
| `other_brand_count` | 其他品牌类数（64） |
| `source_count` | 总数（98） |
| `sources[].source_kind` | `hard_negative` / `other_brand` |
| `sources[].target_class_id` | **仅 hard_negative 有值**：它对应本组哪个品牌的哪一类（如 `0418` 是大众_途岳） |
| `sources[].train` / `.val` | 该来源类别**在教师数据集中**的样本量（不是实际抽取量） |

**统计结果**：98 个来源类别，覆盖 **85 个品牌**、**7 个中文大类**
（SUV 39 / 轿车 33 / 卡车 9 / MPV 6 / 跑车 5 / 轻客 3 / 微面 3）。

**为什么要 `hard_negative`**：如果 unknown 全部来自"完全陌生的品牌"，
模型只要学会"这个品牌我没见过 → unknown"就能拿高分；
但教师测试集里更可能出现的是**同品牌的其他车型**（用户拍了大众途观，而我们只选了大众朗逸）。
加入硬负样本后，模型被迫学习**车型级别**的差异，而不是品牌级别的粗判。

```json
{
  "source_zip": "C:\\Users\\y\\Downloads\\数据集.zip",
  "seed": 20250914,
  "unknown_train_per_source": 20,
  "unknown_val_per_source": 6,
  "unknown_source_count": 98,
  "unknown_hard_negative_count": 34,
  "unknown_other_brand_count": 64,
  "train_total": 7494,
  "val_total": 2422,
  "train_known_total": 5534,
  "train_unknown_total": 1960,
  "val_known_total": 1834,
  "val_unknown_total": 588,
  "unknown_train_ratio": 0.2615,
  "per_class": {
    "train": {
      "0003": { "n": 94, "label": "0003", "name": "宇通客车_宇通T7", "index": 0 },
      "unknown": { "n": 1960, "label": "unknown" }
    },
    "val": {
      "0003": { "n": 31, "label": "0003", "name": "宇通客车_宇通T7", "index": 0 },
      "unknown": { "n": 588, "label": "unknown" }
    }
  },
  "unknown_sources": [ ... 与 unknown_sources.json 的 sources 同构 ... ]
}
```

| 字段 | 数值 | 说明 |
| --- | --- | --- |
| `train_total` | 7,494 | 训练集总数 |
| `train_known_total` | 5,534 | 其中 50 个目标车型 |
| `train_unknown_total` | 1,960 | 其中 unknown |
| `val_total` | 2,422 | 验证集总数 |
| `val_known_total` | 1,834 | 其中 50 个目标车型 |
| `val_unknown_total` | 588 | 其中 unknown |
| `unknown_train_ratio` | 0.2615 | unknown 占训练集 26.2% |

**⚠️ 关键依赖**：`per_class.train.*.n` 被用来计算**训练集类别先验** π：

```
π_c = n_c / N        （N = 7494）
π_unknown = 1960/7494 = 0.2615
π_目标车型 ≈ 110/7494 = 0.0147
```

先验校正公式 `z'_c = z_c − τ·log(π_c)` 就依赖它。
**这个文件删了，τ 就无法生效**（`inference.py` 会退化成 τ=0 并打警告）。

## 8. `outputs/checkpoints/<run>/best.pt` — 模型文件

`torch.load(path, map_location="cpu", weights_only=False)` 之后是一个 dict：

| 键 | 类型 | 含义 |
| --- | --- | --- |
| `model_state` | OrderedDict | 模型权重。**若启用 EMA，这里是 EMA 平滑后的权重** |
| `arch` | str | 骨干名，如 `"resnet18"` / `"resnet50"` |
| `num_classes` | int | 51 |
| `image_size` | int | 输入分辨率，如 224 |
| `class_map` | dict | **完整的类别映射**（与 `configs/class_map.json` 同构） |
| `label_names` | list[str] | 长度 51，最后一个是 `"unknown"` |
| `preprocess` | dict | 预处理参数（见下） |
| `train_config` | dict | **完整的训练配置**（相当于把对应的 `configs/train_*.json` 存了一份） |
| `epoch` | int | 该 checkpoint 对应的轮次 |
| `val_macro_f1` | float | 该轮次验证集 Macro-F1 |
| `ema` | bool | 权重是否经过 EMA |

`preprocess` 的字段：

```json
{
  "mean": [0.485, 0.456, 0.406],
  "std": [0.229, 0.224, 0.225],
  "eval_resize": 256,
  "eval_crop": 224,
  "interpolation": "bilinear"
}
```

| 字段 | 含义 |
| --- | --- |
| `mean` / `std` | ImageNet 归一化参数 |
| `eval_resize` | 推理时短边缩放到多少像素（224 输入 → 256；160 输入 → 183） |
| `eval_crop` | 之后中心裁剪到多少像素（= `image_size`） |
| `interpolation` | 缩放插值方式 |

**因为 dict 是自包含的，重新加载时不需要任何外部文件。**
这正是 `src/verify_reload.py` 能跨进程复现 240/240 条预测的原因。

**文件大小**：resnet18 约 43 MB，resnet50 约 95 MB。

**加载示例**：

```python
from cardex.engine import load_model_from_checkpoint
model, ckpt = load_model_from_checkpoint("outputs/checkpoints/improved_resnet50_224/best.pt")
print(ckpt["arch"], ckpt["image_size"], ckpt["val_macro_f1"])
```

## 9. `outputs/runs/<run>/summary.json` — 实验记录（机器可读）

```json
{
  "run_name": "improved_resnet50_224",
  "config": { ... 完整的训练配置，31 个键 ... },
  "history": [
    {
      "epoch": 1,
      "train_loss": 3.6641,
      "train_acc": 0.2099,
      "val_loss": 3.9102,
      "val_acc": 0.0821,
      "val_macro_f1": 0.0268,
      "unknown_detection_rate": 0.4123,
      "known_false_reject_rate": 0.5312,
      "lr": 0.0013,
      "elapsed_s": 812.4
    },
    ... 共 epochs 条 ...
  ],
  "best": { "macro_f1": 0.95505, "epoch": 14 },
  "final": { "epoch": 14, "train_loss": 1.08023, ..., "val_macro_f1": 0.95505, ... },
  "total_time_s": 10510.4,
  "train_size": 7494,
  "val_size": 2422,
  "num_threads": 12,
  "checkpoints": "E:\\...\\outputs\\checkpoints\\improved_resnet50_224"
}
```

| 键 | 说明 |
| --- | --- |
| `config` | 训练用的完整配置（可直接复现） |
| `history[]` | **逐轮记录**，每轮 10 个字段 |
| `best` | 验证集 Macro-F1 最高的一轮 |
| `final` | 最后一轮（用于判断是否还在提升） |
| `total_time_s` | 总训练耗时（秒） |

> **注意**：`summary.json` 里**没有** `best_val_macro_f1` 字段
> （它是在写完 summary 之后才计算的，只写进了 `val_report.json`）。
> 想取"最佳验证分数"用 `best.macro_f1` 或读 `val_report.json`。

`history[]` 每轮的字段含义：

| 字段 | 含义 |
| --- | --- |
| `train_loss` | 训练集平均损失（含数据增强，所以比验证损失高是正常的） |
| `train_acc` | 训练集准确率。**强增强下这个值不反映真实水平**（C1 只有 0.80，但验证 0.94） |
| `val_loss` | 验证集平均损失 |
| `val_acc` | 验证集准确率 |
| `val_macro_f1` | **验证集 51 类 Macro-F1 —— 选模型的唯一依据** |
| `unknown_detection_rate` | 真实 unknown 中被正确识别的比例 |
| `known_false_reject_rate` | 真实已知车型中被误判为 unknown 的比例 |
| `lr` | 该轮结束时的骨干学习率 |
| `elapsed_s` | 从训练开始到该轮结束的累计秒数 |

## 13. `outputs/runs/<run>/eval_confusion_matrix.csv`

51×51 的 CSV，第一行第一列是占位表头：

```csv
true\pred,宇通客车_宇通T7,吉利汽车_星瑞,...,unknown
宇通客车_宇通T7,29,0,...,2
吉利汽车_星瑞,0,35,...,1
...
unknown,0,1,...,546
```

- **行 = 真实类别**，**列 = 预测类别**（顺序 = `label_names()`，即索引 0~50）
- `M[i][j]` = 真实是第 i 类、被预测成第 j 类的张数
- 对角线是正确预测数，非对角线是错误

**用它快速定位问题**：

```python
import numpy as np, csv
rows = list(csv.reader(open('outputs/runs/improved_resnet18_224/eval_confusion_matrix.csv', encoding='utf-8')))
labels = rows[0][1:]
M = np.array([[int(x) for x in r[1:]] for r in rows[1:]])
i, j = 48, 50                       # 日产_轩逸 被判为 unknown
print(labels[i], '→', labels[j], M[i, j], '次')
```

## 17. `data/` 目录约定

```
data/<split>/<class_dir>/<file>.jpg
```

| 层级 | 取值 | `CarDataset` 如何处理 |
| --- | --- | --- |
| `<split>` | `train` / `val` | 由调用方指定（`--split`） |
| `<class_dir>` | 四位车型 ID（如 `0003`） | 查 `class_map.json` 的 `id_to_index` → 索引 0~49 |
| `<class_dir>` | `unknown` | 固定映射到索引 **50** |
| `<class_dir>` | 其他 | **忽略**（该目录被跳过） |
| `<file>` | `*.jpg` / `*.jpeg` / `*.png` / `*.bmp` / `*.webp` | 读入 → RGB → 变换 |

**样本顺序**（重要，曾引发一个真实 bug）：
`CarDataset` 遍历顺序是 **先按 `class_dir` 名称排序，再按目录内文件名排序**。
`unknown` 因为字符串比较大于 `"0987"`，所以排在**最后**。

> ⚠️ **踩坑记录**：`finalize.py` 与 `ensemble.py` 最初为了对齐标签，对**全部文件名做全局排序**。
> 但 `unknown/` 下的文件名沿用的是**来源类别 ID**（如 `0022_0022.jpg`），
> 全局排序会把它插到 0022 类中间，而 `CarDataset` 把 unknown 排在最后——
> 两者错位导致 Macro-F1 算出 0.0648（而不是 0.95）。
> 现在两个脚本都直接取 `CarDataset.samples` 的顺序，不再自己排序。
