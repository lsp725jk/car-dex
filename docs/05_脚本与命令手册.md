## 1. 数据准备阶段

### 1.1 `inventory.py` — 数据集清点

**作用**：只读 zip 的中央目录（**不解压图片**），结合 `class_info.json` 生成 827 类的统计清单。

**参数**：无。

```bash
python src/inventory.py
```

**输出**：

| 文件 | 内容 |
| --- | --- |
| `outputs/reports/class_inventory.csv` | 827 行：`id, name_from_new, brand, category, body_type, type_info, name_from_old, train, val, total` |
| `outputs/reports/inventory_summary.txt` | 汇总：总规模、每类样本分位数、按大类分布、按车身类型分布、品牌 Top40 |

**实测耗时**：约 3 秒（6.6 GB 压缩包）。

**什么时候用**：换数据集、或想知道"827 类里都有什么"时。

---

### 1.2 `list_candidates.py` — 候选类别明细

**作用**：把 `class_inventory.csv` 按中文大类分组打印成便于人眼挑类的表格。

**参数**：任意个**品牌名**（可选）。

```bash
python src/list_candidates.py                  # 输出全部 827 类，按大类分组
python src/list_candidates.py 奔驰 宝马 奥迪    # 只看指定品牌
```

**输出**：`outputs/reports/candidates.txt`（约 91 KB）

**格式**：

```
====================================================================================================
【SUV】 共 372 类
====================================================================================================
ID    车型名称                              品牌          车身                     train  val  total
----------------------------------------------------------------------------------------------------
0418  大众_途岳                             大众          Compact SUV              119   39    158
0432  奔驰_奔驰GLE                          奔驰          Upper Mid-size SUV       118   39    157
...
```

**什么时候用**：手工选类时（本项目选 50 类之前用过）。

---

### 1.3 `select_classes.py` — 选类与登记

**作用**：读 `configs/selection.json`，校验并生成全部类别相关的配置文件。

**参数**：无（读配置）。

```bash
python src/select_classes.py
```

**输出**：

| 文件 | 内容 |
| --- | --- |
| `classes.txt` ★ | 50 行四位 ID，升序，UTF-8 无 BOM |
| `configs/class_map.json` | 索引 ↔ ID ↔ 名称 ↔ 大类的完整映射 |
| `configs/unknown_sources.json` | 98 个 unknown 来源类别 |
| `outputs/reports/selection_report.txt` | 选类报告（原则、50 类明细、品牌分布、unknown 来源） |

**内置校验**（不通过直接 `SystemExit`）：

- 类别数量必须恰好 50；
- 不得有重复 ID；
- 每个 ID 必须是四位数字且存在于 `class_info.json` 的 827 类中；
- 写出后复查：无 BOM、`\n` 计数恰好 50。

**什么时候用**：
- 首次选类；
- 修改 `configs/selection.json` 之后（**必须重跑**，否则三份配置会不一致）。

### 1.4 `prepare_data.py` — 抽取图片

**作用**：从 6.6 GB zip 中**只抽本项目需要的 9,916 张图**到 `data/`。

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `--force` | flag | 关 | **清空 `data/` 后重新抽取**（慎用） |
| `--seed` | int | 20250914 | unknown 抽样的随机种子 |

```bash
python src/prepare_data.py                    # 增量抽取（已存在的文件跳过）
python src/prepare_data.py --force            # 清空重抽
```

**输出**：

| 路径 | 内容 |
| --- | --- |
| `data/train/<类别>/` | 50 个车型目录 + `unknown/`，共 7,494 张 |
| `data/val/<类别>/` | 50 个车型目录 + `unknown/`，共 2,422 张 |
| `outputs/reports/data_manifest.csv` | 抽取清单（9,916 行） |
| `configs/data_stats.json` | 数据统计（含 `per_class` 的样本量，供先验校正用） |

**实测耗时**：约 10 秒（约 1,040 张/秒）。

**什么时候用**：`classes.txt` 变了之后；或 `data/` 被删了要恢复。
**注意**：`--force` 会删掉整个 `data/` 再重抽，如果正在训练会出错。

## 2. 训练阶段

### 2.1 `train.py` — 训练入口

**作用**：读配置 → 训练 → 逐轮验证 → 保存 checkpoint → 生成日志与报告。

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `--config` | str | **必填** | 训练配置文件路径 |
| `--run-name` | str | 覆盖配置里的 `run_name` |
| `--epochs` | int | 覆盖 |
| `--batch-size` | int | 覆盖 |
| `--lr` | float | 覆盖 |
| `--arch` | str | 覆盖 |
| `--image-size` | int | 覆盖 |
| `--threads` | int | 覆盖 |
| `--limit-train-per-class` | int | 每类只取 N 张（**冒烟测试用**） |
| `--limit-val-per-class` | int | 同上 |
| `--set` | `KEY=VALUE` | 可重复，覆盖**任意**配置项 |

```bash
# 正式训练
python src/train.py --config configs/train_improved.json

# 冒烟测试（约 1 分钟，验证代码能跑通）
python src/train.py --config configs/train_baseline.json --run-name smoke \
       --epochs 2 --limit-train-per-class 12 --limit-val-per-class 6

# 临时改任意参数做对照实验
python src/train.py --config configs/train_improved.json \
       --run-name c1_no_mixup --set mix_prob=0 --set label_smoothing=0.0
```

**输出**：

| 路径 | 内容 |
| --- | --- |
| `outputs/runs/<run>/train.log` | 逐轮训练日志 |
| `outputs/runs/<run>/summary.json` | 配置 + 逐轮历史 + 最优轮次 |
| `outputs/runs/<run>/val_report.json` | 训练结束时的验证结果 |
| `outputs/runs/<run>/val_classification_report.txt` | 逐类 P/R/F1 |
| `outputs/runs/<run>/val_confusion_matrix.npy` | 混淆矩阵 |
| `outputs/checkpoints/<run>/best.pt` | 最优轮 |
| `outputs/checkpoints/<run>/last.pt` | 最后一轮 |
| `outputs/checkpoints/<run>/epoch_XX.pt` | 中期 checkpoint |

**实测耗时**：A 28 min / B 32 min / C1 87 min / C2 175 min。

**中断与恢复**：目前不支持自动续训。若被中断，可用 `last.pt` 手动加载后继续（需要自行写几行代码）。

## 3. 评估与标定阶段

### 3.1 `evaluate.py` — 验证集评估与错误分析

**作用**：对一个 checkpoint 做完整评估，产出混淆矩阵、逐类指标、错误样本、低置信度样本。

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `--checkpoint` | str | **必填** | checkpoint 路径 |
| `--split` | `train`/`val` | `val` | 评估哪个划分 |
| `--out-dir` | str | `outputs/runs/<run>/` | 结果输出目录 |
| `--batch-size` | int | 32 | |
| `--tta-hflip` | flag | 关 | 启用水平翻转 TTA |
| `--threads` | int | CPU 核数 | |
| `--low-conf-threshold` | float | 0.60 | 低置信度样本的判定阈值 |
| `--error-limit` | int | 200 | 错误样本 CSV 最多写多少条 |
| `--amp` / `--no-amp` | flag | **自动** | 默认读取 checkpoint 里记录的 amp 设置，与训练保持一致 |

```bash
python src/evaluate.py --checkpoint outputs/checkpoints/improved_resnet50_224/best.pt --tta-hflip
```

**输出**：

| 文件 | 内容 |
| --- | --- |
| `eval_report.json` | 完整指标（含 `amp` / `tta_hflip` 记录） |
| `eval_classification_report.txt` | 逐类 P/R/F1/support |
| `eval_confusion_matrix.csv` | 51×51 混淆矩阵 |
| `top_confusions.csv` | 最严重的混淆对（前 30） |
| `error_samples.csv` | 错误样本清单（按置信度降序，最多 `--error-limit` 条） |
| `low_confidence_samples.csv` | 低置信度样本清单 |

**实测耗时**：约 3 分钟（resnet50@224，TTA）。

> **注意推理精度**：早期版本默认用 fp32，与训练的 bf16 产生约 0.0005 的指标漂移。
> 现已默认跟随 checkpoint，无需手动指定。

### 3.2 `calibrate.py` — 决策标定（先验校正 + 拒识阈值）

**作用**：一次前向传播缓存 logits，然后在 numpy 上扫描 **17 个 τ × 12 个 t = 204 组**，
按验证集 Macro-F1 选出最优决策规则。

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `--run` | str | — | `outputs/checkpoints/<run>` 下的运行名（二选一） |
| `--checkpoint` | str | — | 直接指定 checkpoint 路径（二选一） |
| `--split` | `train`/`val` | `val` | |
| `--batch-size` | int | 32 | |
| `--tta-hflip` | flag | 关 | **建议开启**，与最终推理一致 |
| `--threads` | int | 12 | |
| `--cache` | str | `runs/<run>/logits_<split>[_tta].npz` | logits 缓存路径；已存在则直接复用 |

```bash
python src/calibrate.py --run improved_resnet50_224 --tta-hflip
```

**输出**：

| 文件 | 内容 |
| --- | --- |
| `calibration.json` | 未标定 / 仅先验校正 / 联合最优三行 + `recommended` + 204 条 `sweep` |
| `calibration_sweep.csv` | 同上，表格版 |
| `logits_val_tta.npz` | logits 缓存（约几 MB） |
| `calibrate.log` | 过程日志 |

**实测耗时**：首次约 2 分钟（含前向传播）；**再次运行 0 秒**（复用缓存）。

**实测输出示例**（C2）：

```
未校准（tau=0, thr=0）        : Macro-F1=0.9550  Acc=0.9447  unk检出=0.896  已知误拒=0.024
仅先验校正（tau=-0.20）       : Macro-F1=0.9592  Acc=0.9492  unk检出=0.939  已知误拒=0.036
先验校正 + 拒识阈值 (-0.20, 0.20): Macro-F1=0.9592  Acc=0.9484  unk检出=0.939  已知误拒=0.039
```

### 3.3 `threshold_analysis.py` — 只扫拒识阈值

**作用**：`calibrate.py` 的一维子集，固定 τ=0 只扫阈值 t。用于报告中单独论证阈值。

| 参数 | 类型 | 默认 |
| --- | --- | --- |
| `--run` | str | **必填** |
| `--checkpoint` | str | 默认用该 run 的 `best.pt` |
| `--split` | str | `val` |
| `--batch-size` | int | 32 |
| `--tta-hflip` | flag | 关 |
| `--thresholds` | str | `0,0.20,0.25,...,0.80` |

```bash
python src/threshold_analysis.py --run improved_resnet18_224 --tta-hflip \
       --thresholds "0,0.2,0.3,0.4,0.5"
```

**输出**：`outputs/runs/<run>/threshold_sweep.csv` 与 `.json`。

**实测结果**（C1）：

```
   阈值  Macro-F1  unknown检出率  已知类误拒率  整体准确率
  0.00    0.9482      0.9184       0.0398     0.9376
  0.20    0.9496      0.9252       0.0442     0.9381  ★
  0.30    0.9487      0.9388       0.0611     0.9331
  ...
  0.60    0.9185      0.9728       0.1341     0.8918
```

**结论**：阈值收益很小（+0.0014），因为主要错误是"高置信度错误"。

### 3.4 `visualize_errors.py` — 错误案例可视化

**作用**：对指定类别，把**训练集样例**与**被误判的验证集样例**并排画出来，
用于人工判断错误原因（我就是用它发现了"同车型多世代"问题）。

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `--run` | str | **必填** | 运行名（读该 run 的 `error_samples.csv`） |
| `--class-id` | str | **必填** | 四位车型 ID，如 `0975` |
| `--n` | int | 6 | 上下各显示几张 |
| `--out` | str | `outputs/reports/error_case_<id>.png` | 输出图路径 |
| `--seed` | int | 7 | 训练集抽样种子 |

```bash
python src/visualize_errors.py --run baseline_resnet18_160 --class-id 0975 --n 6
```

**输出**：一张两行的 PNG（上排训练集、下排误判样例，标题带预测类别与置信度），
同时打印该类错误样本的去向统计。

**前置条件**：必须先跑过 `evaluate.py`（需要 `error_samples.csv`）。

## 4. 交付阶段

### 4.1 `finalize.py` — 候选比选与生成提交文件

**作用**：对若干候选（单模型或集成）分别扫描 (τ, t)，
选出验证集 Macro-F1 最高的配置，并用它重新生成 `predictions.csv`。

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `--candidates` | str… | 空 | 单模型候选（run 名），如 `improved_resnet18_224 improved_resnet50_224` |
| `--ensembles` | str… | 空 | 集成候选，用 `+` 连接成员，如 `improved_resnet18_224+improved_resnet50_224` |
| `--auto` | flag | 关 | 自动收集 `outputs/checkpoints` 下所有已完成且 Macro-F1 > 0.5 的实验 |
| `--split` | str | `val` | |
| `--batch-size` | int | 32 | |
| `--tta-hflip` / `--no-tta` | flag | **默认开** | |
| `--threads` | int | 12 | |
| `--output` | str | `predictions.csv` | 输出路径 |
| `--top-k` | int | 3 | 保留前 K 个候选写完整报告 |

```bash
# 本项目最终使用的命令
python src/finalize.py \
    --candidates improved_resnet18_224 improved_resnet50_224 \
    --ensembles "improved_resnet18_224+improved_resnet50_224"
```

**输出**：

| 文件 | 内容 |
| --- | --- |
| `predictions.csv` ★ | 冠军配置的预测结果 |
| `predictions.meta.json` | 生成配置（冠军、成员、τ、t、TTA、验证分数） |
| `outputs/reports/final_model_choice.json` | 完整比选结果 |
| `outputs/reports/final_model_choice.md` | 比选报告（Markdown 表格） |
| `outputs/reports/final_classification_report_val.txt` | 冠军的逐类报告 |
| `outputs/reports/final_confusion_matrix_val.csv` | 冠军的混淆矩阵 |
| `outputs/reports/final_top_confusions.csv` | 冠军的混淆对 |
| `outputs/runs/finalize_cache/*.npy` | 各成员 logits 缓存 |

**实测耗时**：首次约 4 分钟（要算各成员的前向传播）；有缓存后 **0 秒**。

**实测输出**：

```
排名 improved_resnet18_224+improved_resnet50_224    标定后 0.9604   未标定 0.9587
排名 improved_resnet50_224                          标定后 0.9592   未标定 0.9550
排名 improved_resnet18_224                          标定后 0.9510   未标定 0.9482
★ 最佳配置：improved_resnet18_224+improved_resnet50_224  tau=+0.05  threshold=0.25
```

**⚠️ 若要对外部测试目录推理**：`finalize.py` 目前只支持 `--split`（本地划分）。
对教师指定的外部目录，请用 `predict_batch.py`，或者先用 `ensemble.py --input-dir`。

### 4.2 `predict_batch.py` — 批量推理（单模型）

**作用**：对指定目录或本地划分批量推理，生成 `predictions.csv`。

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `--checkpoint` | str | **必填** | |
| `--input-dir` | str | — | 待推理图片目录（**递归**）（二选一） |
| `--split` | `train`/`val` | — | 改为对本地 `data/<split>` 推理（二选一） |
| `--output` | str | `predictions.csv` | 输出路径 |
| `--batch-size` | int | 32 | |
| `--tta-hflip` | flag | 关 | |
| `--tau` | float | 自动 | 先验校正强度；默认读同 run 的 `calibration.json` |
| `--threshold` | float | 自动 | 拒识阈值；默认同上 |
| `--no-calibration` | flag | 关 | 强制 τ=0, t=0 |
| `--topk-csv` | str | — | 可选，同时导出 Top-5 明细（会显著变慢） |
| `--seed` | int | 42 | |

```bash
# 对教师指定的测试目录推理（正式提交用法）
python src/predict_batch.py \
    --checkpoint outputs/checkpoints/improved_resnet50_224/best.pt \
    --input-dir <教师指定测试图片目录> \
    --output predictions.csv --tta-hflip

# 对本地验证集推理（演练）
python src/predict_batch.py \
    --checkpoint outputs/checkpoints/improved_resnet50_224/best.pt \
    --split val --output predictions.csv --tta-hflip

# 手动指定标定参数
python src/predict_batch.py --checkpoint <pt> --split val \
    --tau 0.05 --threshold 0.25
```

**内置自检**（会打印）：重复 image_id 数、非法标签数、越界 confidence 数、
confidence 的 min/mean/max、预测为 unknown 的比例。

**注意**：这是**单模型**工具。本项目最终提交用的是集成，所以正式提交应该用 `finalize.py`，
或者用 `ensemble.py --input-dir ... --output predictions.csv`。

### 4.3 `infer.py` — 单张图片推理

**作用**：给一张图，输出类别 ID、车型名、confidence、Top-K。

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `--checkpoint` | str | **必填** | |
| `--image` | str | **必填** | |

### 9.1 `start.ps1` / `start.bat` — 一键启动

**双击 `start.bat`** 即可：找 Python → 确认 API Key → 环境自检 → 起服务 → 自动开浏览器。

`start.ps1` 是本体的参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `-Mode web\|cli\|check` | `web` | 起 Web / 起命令行智能体 / 只自检 |
| `-Port <n>` | `5000` | 被占用时自动顺延（最多试 20 个） |
| `-BindHost <ip>` | `127.0.0.1` | 要局域网访问传 `0.0.0.0` |
| `-Offline` | 关 | 强制离线替身，即使已配置 Key |
| `-DeepCheck` | 关 | 自检时加做真实 API + 真实视觉推理 |
| `-NoCheck` | 关 | 跳过自检直接启动 |
| `-NoBrowser` | 关 | 不自动开浏览器 |
| `-Install` | 关 | 先执行 `pip install -r requirements.txt` |
| `-Image <路径>` | — | `cli` 模式：先绑定一张图 |
| `-Question <文本>` | — | `cli` 模式：只问一次就退出 |

```powershell
.\start.ps1                          # 起 Web
.\start.ps1 -Mode check -DeepCheck   # 全量自检
.\start.ps1 -Mode cli                # 命令行对话
.\start.ps1 -Port 8000 -NoBrowser    # 换端口
```

> ⚠️ **`start.ps1` 必须以 UTF-8 with BOM 保存**：Windows PowerShell 5.1 会把无 BOM 的 `.ps1`
> 当成系统 ANSI（中文机器上是 GBK）解码，中文字符串会变乱码并直接导致语法错误。
> 用记事本"另存为"时编码选 **UTF-8 with BOM** 或"带 BOM 的 UTF-8"。
>
> ⚠️ 脚本内**不能**用 `$ErrorActionPreference='Stop'`：PS 5.1 会把外部程序（python.exe）写到 stderr
> 的每一行当成错误记录，一条普通警告就会中断启动。脚本统一用 `Continue` + 显式查 `$LASTEXITCODE`。

### 9.2 `tools/selfcheck.py` — 环境自检

```powershell
python tools/selfcheck.py            # 快检（不联网）：依赖 / 文件 / 权重 / 工具装配
python tools/selfcheck.py --api      # 额外调一次真实 API（失败时自动往下钻做分层诊断）
python tools/selfcheck.py --vision   # 额外做一次真实视觉推理
python tools/selfcheck.py --net      # 网络分层诊断：DNS → TCP 443（逐个 IP）→ TLS → HTTPS
python tools/selfcheck.py --all      # 全量（依赖 + 文件 + 权重 + API + 视觉 + 网络）
python tools/selfcheck.py --json     # JSON 输出
```

`--net` 是排查"连不上接口"的第一手段，它按网络栈自下而上逐层实测，坏在哪层就停在哪层：

```
【网络分层诊断】
  [OK]   ① DNS 解析      api.deepseek.com → 112.49.40.58, 183.253.56.58 · 10 ms
  [WARN] ② TCP 443：1/3 个 IP 不可达        ← CDN 某个边缘节点不通，不影响使用
  [OK]   ③ TLS 握手      TLSv1.3 · 55 ms
  [OK]   ④ HTTPS 可达     GET https://api.deepseek.com → HTTP 401（未带 Key，属正常）
```

> TCP 那一层是**逐个 IP** 测的。`api.deepseek.com` 挂在 CDN 后面，
> 实测出现过"3 个 A 记录里 1 个黑洞、另 2 个 6ms"的情况；
> 只测第一个 IP 会给出误导性结论。
> 另外 `--api` 失败时若判定为网络类错误，也会自动调起这套分层诊断。

它不只检查 `import`，还把任务书的硬性约束编成了断言：`classes.txt` 的行数/位数/升序/BOM/
不含 unknown、`predictions.csv` 的表头、集成权重是否齐全、工具数量是否满足"≥1 视觉 + ≥2 其他"、
`.env.local` 是否仍被 `.gitignore` 覆盖。

**退出码**：`0` = 无 FAIL（可有 WARN）；`1` = 有 FAIL（不应启动）。

### 9.3 `tools/e2e_test.py` — 端到端测试

分两段，可单独跑：

| 阶段 | 内容 | 是否需要 API Key | 耗时 |
| --- | --- | --- | --- |
| **A 工具层** | 直接调 `ToolRegistry.execute`，验证参数校验 / 前置门禁 / 错误码 / 拒识分支 | 否 | 约 7 s |
| **B 模型层** | 8 个真实对话场景、13 轮，验证工具链、多轮会话、拒识话术 | **是** | 约 40 s |

```powershell
python tools/e2e_test.py                    # A + B
python tools/e2e_test.py --stage A          # 只跑工具层
python tools/e2e_test.py --stage B --only S3,S5   # 只跑指定场景
python tools/e2e_test.py --offline          # 用离线替身跑 B（对照用）
python tools/e2e_test.py --cleanup          # 跑完删掉测试写入的档案记录
python tools/e2e_test.py --json
```

场景一览（B 段）：

| 编号 | 场景 | 验证点 |
| --- | --- | --- |
| S1 | 纯文本问候 | 不需要工具时不要乱调工具 |
| S2 | 上传图后要求识别 | 视觉识别由**模型自己**发起，不是外部预算好 |
| S3 | 识别 → 查资料 → 写档案 | **单轮内 ≥3 个工具串联**（任务书 5.3） |
| S4 | 同会话三轮追问 | 第 2 轮不重新识图也能答对（任务书 5.4） |
| S5 | 范围外车型 | 如实拒识、不编造、不写档案（任务书 5.5） |
| S6 | 没传图就要识别 | 异常反馈友好、智能体不崩 |
| S7 | 档案检索与统计 | 业务操作类工具 |
| S8 | 问支持范围外的车型 | 说明边界，不硬答 |

**退出码**：`0` = 全过；`1` = 有 FAIL。
