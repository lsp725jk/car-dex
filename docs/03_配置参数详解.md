# 03 配置参数详解

本文档逐字段解释训练配置（`configs/train_*.json`）里的**每一个参数**：
它是什么意思、本项目取什么值、调大调小会怎样、什么情况需要动它。

`train.py` 读取这些 JSON 后交给 `src/cardex/engine.py::train_model()` 执行。

## 1. 模型与输入

### `run_name`（字符串，**必填**）

- **含义**：本次实验的名字。它决定两个输出目录：
  - `outputs/checkpoints/<run_name>/` —— 模型文件
  - `outputs/runs/<run_name>/` —— 日志与指标
- **本项目值**：如 `improved_resnet18_224`
- **注意**：**同名会覆盖**。重跑实验前建议改名（如加 `_v2` 后缀），或先备份 `outputs/`。
- **命令行覆盖**：`python src/train.py --config ... --run-name my_test`

### `arch`（字符串，**必填**）

- **含义**：骨干网络。
- **可选值**（见 `src/cardex/models.py::SUPPORTED`）：
  | 值 | 参数量 | 本地权重文件 | 本项目用途 |
  | --- | --- | --- | --- |
  | `resnet18` | 11.2 M | `resnet18-f37072fd.pth` | A / B / C1 |
  | `resnet50` | 23.5 M | `resnet50-0676ba61.pth`（**V1**） | C2 |
  | `wide_resnet50_2` | 66.8 M | `wide_resnet50_2-9ba9bcbe.pth` | 未用（CPU 太慢） |
- **调大的代价**（纯 CPU 实测，含数据加载）：
  | 配置 | 吞吐（bf16 开） | 单轮耗时 |
  | --- | --- | --- |
  | resnet18 @160 | 68.6 img/s | 1.82 min |
  | resnet18 @224 | 36.3 img/s | 3.44 min |
  | resnet50 @160 | 25.9 img/s | 4.82 min |
  | resnet50 @224 | 14.0 img/s | 8.95 min |
- **实际收益**：resnet18→resnet50 在同一配方下只提升 **+0.0068** Macro-F1，训练时间却翻倍。
  **除非算力充裕，优先调 `image_size` 而不是 `arch`。**

> ⚠️ **坑**：`ResNet50_Weights` 的 V1 与 V2 是不同文件。若误写 `IMAGENET1K_V2`，
> torchvision 会尝试下载 `resnet50-11ad3fa6.pth`，无网环境下抛 `RuntimeError`。

### `pretrained`（布尔）

- **含义**：是否加载 ImageNet 预训练权重。
- **本项目值**：`true`（**始终保持 true**）。
- **为什么必须 true**：本项目每类只有 80~186 张训练图（共 7,494 张），
  从头训练 51 类分类器会严重欠拟合。用 ImageNet 预训练做迁移学习是精度的基础。
- **什么时候设 false**：只在做"是否用预训练"的对照实验时。

### `image_size`（整数）

- **含义**：网络输入的正方形边长（像素）。
- **本项目值**：`160`（基线） / `224`（改进）。
- **作用**：这是**本任务最有效的单一手段**。细粒度车型分类依赖格栅条数、灯组轮廓、
  车标位置等小尺度线索；160×160 下这些细节只有几个像素，224 下才具备可分性。
- **实测收益**：160→224（配合强增强）带来 **+0.1007** Macro-F1。
- **权衡**：耗时按面积平方增长（160→224 是 1.96 倍像素）。
- **常见取值**：128 / 160 / 192 / 224 / 256 / 288。224 是 ImageNet 的标准输入，也是性价比拐点。

## 2. 数据增强

### `train_transform`（字符串）

- **含义**：选用哪一套训练期增强流水线。取值由 `src/cardex/data.py::build_transform()` 识别。
- **可选值**：

| 值 | 流水线 | 适用 |
| --- | --- | --- |
| `baseline_train` | RandomResizedCrop + HFlip | 基线对照 |
| `moderate_train` | RandomResizedCrop + HFlip + ColorJitter + RandomErasing | 中等强度 |
| `strong_train` | RandomResizedCrop + HFlip + ColorJitter + RandAugment + RandomErasing | 主配方 |
| `eval` | Resize + CenterCrop（**无随机性**） | 验证/推理（由代码自动使用，不用写在配置里） |

> **重要**：验证与推理**始终**使用 `eval` 流水线（确定性的 Resize + CenterCrop），
> 与 `train_transform` 的取值无关。这是保证验证指标可比的前提。

### `aug`（对象）—— 增强参数集合

#### `aug.crop_scale`（两元素数组）
- **含义**：`RandomResizedCrop` 的面积占比范围 `[下界, 上界]`。
- **本项目值**：基线 `[0.70, 1.0]`，改进 `[0.50, 1.0]`。
- **作用**：下界越小，模型越经常"只看到车头或车尾的一部分"。
  这逼迫它整合格栅、灯组、车身轮廓等多个线索，而不是依赖某一个显著区域（如车标）。
- **为什么改进模型要放宽到 0.5**：数据分析发现类内多样性高（近重复率 0.00%），
  且真实用户照片经常是特写或局部，需要模型对"局部可见"鲁棒。
- **风险**：下界太低（如 0.2）会切掉过多语义信息，反而掉分。

#### `aug.hflip`（浮点 0~1）
- **含义**：水平翻转概率。
- **本项目值**：`0.5`。
- **注意**：**不使用垂直翻转**——车辆几乎不会倒置出现，垂直翻转会产生不存在的样本分布。

#### `aug.eval_resize_ratio`（浮点）
- **含义**：推理时"短边缩放比例"。推理流程是：
  `短边缩放到 image_size × ratio` → `中心裁剪 image_size`。
- **本项目值**：`1.142857`（= 256/224）。
- **作用**：先把图放大一点再裁，相当于保留更多上下文，比"直接缩放到 224"精度更高（标准 ImageNet 做法）。
  224 输入对应短边缩放到 **256**；160 输入对应缩放到 **183**。
- **⚠️ 必须在训练与推理间保持一致**。本项目把它存进 checkpoint 的 `preprocess` 字段，
  推理代码自动读取，所以不会不一致。
- **改动风险**：改了它，已有 checkpoint 的推理精度会下降。

#### `aug.color_jitter`（布尔）+ 四个强度参数
- **含义**：颜色抖动开关与强度。
- **本项目值**（strong）：`brightness=0.35, contrast=0.35, saturation=0.35, hue=0.08`
- **作用**：教学图片多为展厅/户外商业图，色调统一；真实用户照片白平衡、曝光差异大。
  颜色增强能显著缩小这一域差异。
- **hue 为什么只有 0.08**：色相偏移过大（>0.1）会把白车变成蓝车，语义失真。

#### `aug.randaugment`（布尔）+ `ra_num_ops` + `ra_magnitude`
- **含义**：RandAugment 开关、每次随机施加的操作个数、统一强度（1~10）。
- **本项目值**：`true, 2, 7`（基线未使用）。
- **作用**：从一组图像操作（旋转、剪切、色调分离、锐化等）中随机挑 2 个，以强度 7 施加。
- **代价**：训练任务显著变难，**收敛变慢**——C1 前 5 个 epoch 一直落后于基线，到第 6 轮才反超。

#### `aug.random_erasing`（浮点 0~1）
- **含义**：随机擦除概率（在 ToTensor 之后对张量做）。擦除区域面积占 `[0.02, 0.15]`。
- **本项目值**：`0.25`（改进） / `0.15`（中等） / 未设（基线）。
- **作用**：随机遮掉一小块，抑制模型对单一显著区域的过强依赖。

## 3. 训练循环

### `epochs`（整数，**必填**）
- **含义**：训练轮数。
- **本项目值**：12（A/B）/ 18（C1）/ 14（C2、备用）。
- **与 `scheduler` 的关系**：余弦退火的学习率曲线是按 `epochs` 铺开的，
  所以**改 `epochs` 会改变整条学习率曲线**，不是简单"多跑几轮"。
- **经验**：强增强配方需要更多轮才收敛（C1 用 18 轮，且第 18 轮才达到最佳）。

### `batch_size`（整数）
- **含义**：每个批次多少张图。
- **本项目值**：`32`。
- **作用**：影响 BN 统计的稳定性与显存/内存占用。CPU 训练下主要受内存限制。
- **注意**：改小（如 8）会明显降低 BN 稳定性，需要同步降低学习率。

### `num_workers`（整数）
- **含义**：DataLoader 的子进程数。
- **本项目值**：**`0`（必须）**。
- **为什么必须 0**：运行环境的沙箱**禁止创建命名管道**，
  `DataLoader(num_workers>0)` 依赖 multiprocessing 的 Pipe，会直接抛
  `PermissionError: [WinError 5] 拒绝访问`。
- **代价**：数据加载与计算串行，实测约损失 30% 吞吐
  （数据加载单独 188 img/s，计算单独约 70 img/s，串行后合成约 50 img/s）。
- **在不受限制的环境下**：改成 `4` 并配合 `persistent_workers=True` 即可提速。

### `grad_clip`（浮点，0 表示关闭）
- **含义**：梯度范数裁剪阈值。
- **本项目值**：`5.0`。
- **作用**：防止梯度爆炸。本项目在早期调试中发现过"学习率过大导致验证损失飙到 2889"的情况，
  加裁剪是必要的安全网。

### `seed`（整数）
- **含义**：全局随机种子（`random` / `numpy` / `torch`）。
- **本项目值**：`42`（训练）；数据抽样用 `20250914`。
- **作用**：保证可复现。已验证：固定种子后重跑选类与抽数流程，4 个产物 SHA256 完全一致。

### `log_interval`（整数）
- **含义**：每多少个 step 打印一次训练进度。
- **本项目值**：`60`（一个 epoch 共 235 个 step）。

### `checkpoint_interval`（整数）
- **含义**：每多少轮保存一个中期 checkpoint（`epoch_XX.pt`）。
- **本项目值**：3 或 4。
- **作用**：任务书 4.2.3 要求"保留中期 checkpoint 和最终模型"。
- **注意**：`best.pt` 与 `last.pt` **每轮都会保存**，与这个参数无关。

## 4. 优化器与学习率

### `optimizer`（字符串）
- **可选值**：`sgd` / `adamw`
- **本项目值**：`sgd`（全部实验）。
- **为什么用 SGD**：微调预训练 CNN 的常规选择，泛化通常略优于 Adam 系；
  且对学习率更敏感、行为更可预测。
- **什么时候换 adamw**：数据量很小、或骨干是 Transformer 类结构时。

### `lr`（浮点，**最关键的超参**）
- **含义**：初始学习率（指 `param_groups` 里骨干的学习率）。
- **本项目值**：`0.01`。
- **⚠️ 踩坑记录**：最初把分类头的学习率设成骨干的 **10 倍**（`head_lr_mult=10`），
  结果 `lr=0.1` 直接把模型打崩——训练损失从 4.87 涨到 14.4，验证损失从 41 飙到 **2889**，
  Macro-F1 卡在 0.007。改成 `head_lr_mult=1.0` 后立刻正常。
- **调参建议**：
  - 太大 → 损失震荡或发散（表现为 `val_loss` 远大于 `log(51)≈3.9`）；
  - 太小 → 收敛慢、欠拟合；
  - batch size 变化时，学习率应大致按比例调整。

### `momentum`（浮点）
- **含义**：SGD 动量系数。
- **本项目值**：`0.9`。使用 `nesterov=True`。

### `weight_decay`（浮点）
- **含义**：L2 正则化系数。
- **本项目值**：`1e-4`。

### `head_lr_mult`（浮点）
- **含义**：**分类头**学习率相对骨干的倍数。
- **本项目值**：`1.0`（即分类头与骨干同学习率）。
- **背景**：分类头是新初始化的，骨干是预训练的，常见的做法是给分类头更大的学习率
  （`3~10` 倍）。但本项目实测 **10 倍会发散**（见上面 `lr` 的踩坑记录），
  所以统一用 `1.0`。
- **如果想用差分学习率**：建议从 `2.0` 开始试，同时把 `lr` 降到 `0.005` 左右。

### `scheduler`（字符串）
- **可选值**：`cosine` / `step` / `none`
- **本项目值**：`cosine`。
- **作用**：每个 step 按余弦曲线衰减学习率，从峰值平滑降到 0。
  配合 warmup 是本项目的标准配置。
- **注意**：本项目是**按 step 更新**（不是按 epoch），所以曲线更平滑。

### `warmup_epochs`（整数）
- **含义**：学习率从 0 线性升到峰值的轮数。
- **本项目值**：1（A/B/备用） / 2（C1/C2）。
- **作用**：分类头是随机初始化的，训练初期梯度很大；
  预热可以防止它在头几轮就把预训练特征破坏掉。
- **为什么改进模型用 2**：强增强+MixUp 让初期梯度更噪，需要更长的预热。

## 5. 损失函数相关

### `label_smoothing`（浮点 0~1）
- **含义**：标签平滑系数 ε。真实类目标值从 1 变成 `1-ε+ε/C`，其余类从 0 变成 `ε/C`（C=51）。
- **本项目值**：`0.0`（A/B） / `0.1`（C1/C2） / `0.05`（备用）。
- **作用**：防止模型过度自信，改善校准，通常对 Macro-F1 有正收益。
- **副作用**：训练损失的最低值被抬高（不再趋近 0），所以**不能用训练损失判断收敛**。

### `class_weight`（字符串）
- **可选值**：`none` / `inverse` / `sqrt_inverse`
- **本项目值**：`none`（A/C1/C2） / `inverse`（B）。
- **计算公式**（`inverse`）：
  ```
  w_c = N / (C · n_c)     然后除以均值归一化
  ```
  其中 `N` 是训练样本总数，`C=51` 是类别数，`n_c` 是第 c 类的样本数。
  这样第 c 类对总损失的**名义贡献**是 `n_c · w_c ∝ 1`，与类别大小无关。
- **`sqrt_inverse`** 是它的温和版：`w_c ∝ 1/√n_c`，贡献正比于 `√n_c`。
- **本项目结论（重要）**：
  - 单独使用 `inverse` 会让 Macro-F1 **下降 0.0047**（因为它把 unknown 检出率从 82% 压到 59%）；
  - 但它把已知类误拒率从 10.3% 降到 4.7%；
  - **配合推理端一次负向先验校正（τ=−0.40）后净赚 +0.0122**。
  - 所以：**类别权重不能单独调，必须与推理端的 τ 联合调优**。
- **为什么 C1/C2 用 `none`**：基线模型的先验扫描显示 τ=0 处 Macro-F1 最高，
  说明无权重模型的隐式先验恰好是最优的。这是数据驱动的决策，不是拍脑袋。

### `unknown_weight_mult`（浮点）
- **含义**：在 `class_weight` 之上，对 unknown 类额外乘的倍数。
- **本项目值**：`1.0`（等于不额外加权）。
- **什么时候用**：如果发现模型"不敢说不认识"（unknown 检出率低），可以调到 `1.5~2.0`。
- **注意**：`class_weight: "none"` 时这个参数**不起作用**。

### `mixup_alpha` / `cutmix_alpha` / `mix_prob`（浮点）
- **含义**：
  - `mixup_alpha`：MixUp 的 Beta 分布参数 α（两张整图按 `λ ~ Beta(α,α)` 混合）；
  - `cutmix_alpha`：CutMix 的 Beta 分布参数 α（把一张图的矩形区域贴到另一张上）；
  - `mix_prob`：一个 batch 施加混合增强的概率（MixUp 与 CutMix 各 50% 概率二选一）。
- **本项目值**：C1/C2 `0.2 / 0.5 / 0.35`；A/B/备用 `0 / 0 / 0`（关闭）。
- **作用**：强正则化手段，抑制过拟合，提升泛化。
- **代价**：训练任务变难、收敛变慢；且训练期的"准确率"不再有直观意义
  （因为一半样本的标签本身就是混合的）。
- **关闭方式**：把 `mix_prob` 设为 `0`。

## 6. 评估与推理相关

### `ema_decay`（浮点，0 表示关闭）
- **含义**：权重的指数滑动平均衰减率。`0.999` 意味着有效平均窗口约 1000 个 step。
- **本项目值**：`0.999`（C1/C2/备用） / `0.0`（A/B）。
- **作用**：训练时维护一份"平滑后的权重"，评估时用它而不是当前权重。
  能显著降低验证指标的波动，通常带来 +0.5~1%。
- **注意**：
  - 前期 EMA 会"滞后"——C1 前 2 个 epoch 的 EMA 权重还包含大量早期权重，
    所以早期指标偏低是正常的；
  - 保存进 `best.pt` 的 `model_state` **就是 EMA 权重**（checkpoint 里有 `ema: true` 标记）。
- **步数与衰减的关系**：`0.999` 配 235 step/epoch 时窗口约 4.3 个 epoch；
  如果数据集很小（几十 step/epoch），应该调小（如 `0.99`），否则 EMA 几乎不动。

### `tta_hflip`（布尔）
- **含义**：推理时是否做水平翻转 TTA——同一张图正着与翻转各跑一次，
  对 log-softmax 取平均再 softmax。
- **本项目值**：`true`（改进模型） / `false`（基线）。
- **收益**：基线开启 TTA 后从 0.8475 提到 0.8588（**+0.011**）。
- **代价**：推理耗时翻倍。
- **什么时候该开**：只要推理时间不是瓶颈，就该开。
- **注意**：`tta_hflip` 是训练配置里的字段，但训练过程中**每轮的验证评估也会用到它**，
  所以它同时影响"选模型的依据"和"最终推理"。

### `amp`（布尔）
- **含义**：CPU bfloat16 混合精度（`torch.autocast('cpu', dtype=torch.bfloat16)`）。
- **本项目值**：`true`。
- **作用**：AMD Zen4 支持 AVX512-BF16，实测**吞吐提升约 1.5 倍**：
  | 配置 | fp32 | bf16 | 提升 |
  | --- | --- | --- | --- |
  | resnet18 @160 | 44.9 img/s | **68.6 img/s** | 1.53× |
  | resnet18 @224 | 24.3 img/s | **36.3 img/s** | 1.49× |
- **安全性**：损失仍在 **float32** 中计算（代码里显式 `logits.float()`），
  只是前向与反向的内部运算用 bf16，实测对精度无可见影响。
- **⚠️ 一致性坑**：`src/evaluate.py` 曾默认用 fp32 评估，
  与训练时的 bf16 产生约 **0.0005** 的指标漂移。
  现已改为**默认读取 checkpoint 里记录的 `amp` 设置**，两侧完全一致
  （基线 0.847508 / 类别平衡 0.842818 / 改进 0.948215）。

### `threads`（整数）
- **含义**：`torch.set_num_threads()` 的值。
- **本项目值**：`12`。
- **为什么是 12 而不是 16（逻辑核数）**：实测 16 线程会因**超订阅**反而变慢。
  完整训练步（含数据加载）实测吞吐：

  | 线程 | 吞吐 | 推算单轮 |
  | --- | --- | --- |
  | 6 | 36.5 img/s | 3.42 min |
  | 8 | 39.8 img/s | 3.14 min |
  | 10 | 42.8 img/s | 2.92 min |
  | **12** | **46.2 img/s** | **2.70 min** |
  | 16 | 38.2 img/s | 3.27 min |

  **12 线程比 16 线程快 17%**。换机器时建议重新测一遍。
- **命令行覆盖**：`--threads 8`

## 8. 最小可跑配置

如果你想从零写一个自己的配置，以下字段是必需的（其余走默认值）：

```json
{
  "run_name": "my_experiment",
  "arch": "resnet18",
  "image_size": 224,
  "train_transform": "strong_train",
  "epochs": 15,
  "lr": 0.01
}
```

默认值（`engine.py` 里 `cfg.get(...)` 的兜底）：`pretrained=true`、`batch_size=32`、
`optimizer=sgd`、`momentum=0.9`、`weight_decay=1e-4`、`head_lr_mult=10.0`（**注意这个默认偏大，建议显式写 1.0**）、
`scheduler=cosine`、`warmup_epochs=0`、`label_smoothing=0`、`class_weight=none`、
`ema_decay=0`、`tta_hflip=false`、`grad_clip=0`、`seed=42`、`amp=false`、`threads=CPU 核数`。

## 9. 常用改动配方

| 我想…… | 改什么 |
| --- | --- |
| 提升精度 | 先调 `image_size`（160→224），再考虑 `epochs`、`ema_decay`、`tta_hflip` |
| 加快训练 | 降 `image_size`、降 `arch`、关 `mix_prob`、降 `epochs` |
| 缓解过拟合 | 开/加强 `mix_prob`、`randaugment`、`random_erasing`、`label_smoothing`、`ema_decay` |
| 提升 unknown 检出率 | 调大 `class_weight=inverse` + `unknown_weight_mult=1.5`，**并且**去跑 `calibrate.py` 找负的 τ |
| 减少误拒（known 被判 unknown） | 跑 `calibrate.py`，用正的 τ 或提高拒识阈值 |
| 换个骨干对比 | 改 `arch`（注意本地权重必须存在） |
| 做一个轻量冒烟测试 | `--epochs 2 --limit-train-per-class 12 --limit-val-per-class 6` |
